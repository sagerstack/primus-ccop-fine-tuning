# Prometheus & Prometheus 2 (Kim et al., ICLR 2024 / 2024)

**Category**: Academic judge (fine-tuned open-source evaluator LM)
**Canonical sources**:
- Prometheus 1: [Kim et al., ICLR 2024 — arXiv:2310.08491](https://arxiv.org/abs/2310.08491)
- Prometheus 2: [Kim et al., 2024 — arXiv:2405.01535](https://arxiv.org/abs/2405.01535)
- Feedback Collection dataset: [HuggingFace](https://huggingface.co/datasets/prometheus-eval/Feedback-Collection)
- Code: [prometheus-eval/prometheus-eval](https://github.com/prometheus-eval/prometheus-eval)

## Scoring mechanics

- **Backbones**: Prometheus 1 = Llama-2-13B fine-tuned on Feedback Collection. Prometheus 2 = Mistral-7B and Mixtral-8x7B; the final Prometheus 2 models are produced by **weight-merging** two separately trained evaluator LMs (one trained on direct-assessment format, one on pairwise).
- **Scale**: Integer 1-5 anchored to rubric descriptors (fine-grained rubrics per instance).
- **Output format**: `Feedback: <CoT justification> [RESULT] <integer>` for direct assessment; pairwise output returns `[A]` or `[B]`.
- **Composite**: Per-dimension score; no fixed aggregation — the user defines the rubric, and the model emits one score per rubric.

## Prompt scaffolding

Prometheus expects a structured prompt with four components, **all required**:

1. **Instruction** (the question)
2. **Response** (model output being evaluated)
3. **Reference answer** (gold reference — this is what unlocks Prometheus's high agreement)
4. **Score rubric** — described **at instance granularity**:
   - Criteria description (1-3 sentences of what's being measured for THIS instance)
   - Score descriptions for each of the 5 levels (each 1-3 sentences, instance-specific)

## Ground-truth requirements — the **instance-specific rubric** design

Prometheus's crucial GT innovation (from the Feedback Collection dataset design):

- Each instance has its OWN 5-level rubric, not a universal rubric.
- Per-instance rubric construction: GPT-4 is prompted to produce the score descriptors tailored to the question and reference answer, then human-verified (Feedback Collection method).
- Each rubric descriptor is **concrete and instance-grounded** (e.g., "Score 2: response mentions the CII criticality but fails to connect it to Clause 5.3.1's individual-accountability requirement") rather than generic ("partially correct").

### Feedback Collection dataset schema

- 1,000 seed score rubrics (50 human-seeded, expanded via GPT-4 brainstorming)
- 20,000 instructions (questions)
- 100,000 responses with GPT-4 language feedback
- Each row: `(instruction, reference_answer, rubric, response, score, feedback)`

## Annotation cost

- **Seed rubrics**: ~50 human-authored rubrics served as seeds; the rest were generated by GPT-4 with human verification.
- **For adoption in our use case**: generating instance-specific rubrics via GPT-4 for our 118 test cases is feasible (cost ~$10-30 in API calls), but human verification by a CCoP expert would add 5-15 minutes per rubric (~10-30 hours total).

## Bias / reliability controls

- **Open-source + reproducible**: fixed weights, local execution → no silent version drift (vs Claude/GPT-4 API).
- **Instance-specific rubric**: anchors score descriptors to concrete content; reduces ambiguity-induced variance.
- **Weight merging** (Prometheus 2): combines direct-assessment and pairwise capabilities in one model without performance regression.
- Does NOT fix: position bias in pairwise (still reports asymmetry); self-enhancement bias.

## Reported agreement numbers

- Prometheus 1: Pearson 0.897 with human evaluators on 45 customized rubrics; GPT-4 is 0.882 (essentially ties GPT-4).
- Prometheus 2: highest correlation with both humans and proprietary LM judges among open evaluator LMs — Pearson gain 0.2 over prior open baselines on four direct-assessment benchmarks (Vicuna Bench, MT-Bench, FLASK, Feedback Bench).

## Reported limitations

- Prometheus 1 (13B) underperforms GPT-4 when **reference answer is absent**; reference-anchoring is load-bearing.
- Prometheus 2 is still weaker than frontier proprietary models on adversarial / edge-case rubrics where GPT-4's reasoning advantage matters.
- Evaluator bias not fully eliminated: both Prometheus models show some self-preference when evaluating Mistral-family outputs.

## Citation / fact grounding

Not built-in — grounding is the USER's responsibility via the reference answer and rubric fields. For CCoP, we would inject expected clause text into the reference, and specify factual grounding as a rubric criterion.

## Domain fit for cybersecurity compliance QA

- **Directly applicable**: reproducibility (local execution, pinned weights) is a strong fit for a dissertation requiring defensible methodology. No silent API drift between runs separated by weeks.
- **Instance-specific rubrics** map well to our benchmark diversity — a B03 conditional-compliance rubric needs different anchors than a B21 fabrication-detection rubric.
- **Tradeoffs**: Prometheus 2's best variant (Mixtral-8x7B) needs ~90GB VRAM in FP16 (or quantized to ~24GB in Q4); Mistral-7B variant runs on a single RTX 4090. Fine-tuning on CCoP-specific rubrics is feasible but requires ~200 rubric exemplars for meaningful gain.
- **Cost**: API cost goes to ~$0 (self-hosted), but infra cost (GPU rental $1-2/hr or owned GPU) dominates. For 118 test cases × 5 dimensions × 3 samples = 1,770 scoring calls, Prometheus-2-7B completes in <15 minutes on a single GPU.

## Concrete borrowable patterns

1. **Instance-specific rubric field** added to our GT schema (new `instance_rubric: {criteria, score_descriptors: [str, str, str, str]}`).
2. **Feedback before score** output convention — forces CoT before integer commit.
3. **Reference-anchored** judging as a first principle (we already do this; Prometheus validates the approach).
