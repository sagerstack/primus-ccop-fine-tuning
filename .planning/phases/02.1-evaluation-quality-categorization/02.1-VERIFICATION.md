### Gaps Summary

One functional gap blocks complete goal achievement:

**Per-Benchmark Quality Breakdown Table Key Mismatch (CLI):** The `summary.by_benchmark` dict uses full benchmark names as keys (e.g., "B1_CCoP_Applicability_Scope") because `_group_by_benchmark()` at `evaluate_model.py:665` calls `benchmark_type.value`. However, `quality_categories["by_benchmark"]` uses short-name keys (e.g., "B1") because `_aggregate_quality_categories()` at `evaluate_model.py:405` calls `benchmark_type.short_name`. 

In the CLI at `evaluate.py:319`, the code iterates `summary.by_benchmark.keys()` (full names) and at line 322, does `by_benchmark_data.get(benchmark, {})` against the quality_categories dict (short names). Since "B1_CCoP_Applicability_Scope" != "B1", the lookup always returns `{}`, making `bench_groups` empty. The per-benchmark breakdown table renders with headers but zero data rows.

Additionally, the sorting lambda `int(x[1:]) if x[1:].isdigit() else 0` at line 319 also fails for full names since "1_CCoP_Applicability_Scope".isdigit() is False, causing all benchmarks to sort with key 0.

**Fix options:**
1. Change the CLI to extract short_name from full benchmark keys before lookup (e.g., `benchmark.split('_')[0]`)
2. OR change `_group_by_benchmark` to use `short_name` keys (would affect other consumers)
3. OR change `_aggregate_quality_categories` to use `.value` keys (would need CLI to iterate full names)

The simplest fix is option 1 -- CLI extracts short name before looking up in quality_categories.
