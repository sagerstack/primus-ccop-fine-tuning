## Decisions Made

**1. Summary table structure:**
- Replaced two old tables (Evaluation Summary + Results by Benchmark) with categorized quality display
- Run info header (model/tests/passed/failed/duration/mode) shown as plain text before tables
- Overall Quality Summary: single table with all 6 metrics as columns, 3 quality groups as rows, group average in last column
- Per-Benchmark Quality Breakdown: all 6 metrics as columns, benchmarks + groups as rows with tree structure

**2. Per-benchmark display approach:**
- Show all 6 individual metrics per benchmark (not just group averages)
- First row for each benchmark shows benchmark name (e.g., "B1")
- Subsequent rows show group names with tree indent (e.g., "  └─ Model-RAG Grounding")
- Allows at-a-glance comparison of individual metrics across benchmarks

**3. Per-test-case reorganization:**
- Model Response Quality section first: LLM Judge dimensions + RAGAs: answer_correctness + RAGAs: answer_relevancy
- Model-RAG Grounding section second: RAGAs: faithfulness
- Retrieval Quality section third: RAGAs: context_recall + RAGAs: context_precision
- Color-coded group headers: cyan for Model Response Quality, magenta for Model-RAG Grounding, yellow for Retrieval Quality
- Diagnostic intent: users can immediately tell if retrieval is weak, model ignores context, or response quality is poor

**4. Metric labeling consistency:**
- Use QualityGroup.get_display_name() for all metric labels
- Ensures "RAGAs:" prefix on all RAGAs metrics, "LLM Judge" label for judge score
- Single source of truth for display names
