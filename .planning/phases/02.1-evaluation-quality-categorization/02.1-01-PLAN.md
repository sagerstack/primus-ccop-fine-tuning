  <name>Task 2: Implement quality category aggregation in EvaluateModelUseCase</name>
  <files>
    src/application/use_cases/evaluate_model.py

  <action>
    Add a new method `_aggregate_quality_categories` to EvaluateModelUseCase that computes quality group scores at per-benchmark and overall levels. Call it from `_generate_summary` and attach results to the EvaluationSummaryDTO.

    1. Add import: `from domain.value_objects.quality_group import QualityGroup`

    2. Add method `_aggregate_quality_categories(self, results: List[EvaluationResult], by_benchmark: Dict) -> Dict[str, Any]`:

       Logic:
       a. Determine evaluation mode from results: check first result's evaluation_mode (all results in a run share the same mode). If mode is "llm-only", rag_only_groups = QualityGroup.get_rag_only_groups().

       b. Group results by benchmark (use test_case.benchmark_type.short_name as key, e.g., "B1").

       c. For each benchmark, for each QualityGroup:
          - If group.name is in rag_only_groups and mode is "llm-only": set all metrics to None (N/A), group average = None.
          - Otherwise, for each metric in group.metrics:
            - If metric == "llm_judge": collect overall_score from each result in this benchmark.
              - For rule-based benchmarks (B1, B2, B4, B5, B6, B21), the overall_score IS the rule-based score. Use it directly as the LLM Judge metric value (it's already 0-1 normalized).
              - For LLM judge benchmarks, the overall_score is already normalized to 0-1 (ScoringService normalizes by /3).
              - Compute simple average across test cases.
            - If metric is a RAGAs metric name (context_recall, context_precision, faithfulness, answer_correctness, answer_relevancy):
              - For each result in benchmark: look at result.ragas_evaluation
              - If ragas_evaluation is None or ragas_evaluation.evaluation_error is True: count score as 0.0
              - Otherwise: find the RagasMetricScore with matching name. If applicable=True, use score; if applicable=False, skip (don't count toward average).
              - Compute simple average across applicable test cases. If no applicable test cases, value = None.
          - Group average = mean of non-None metric values in the group. If all None, group average = None.
          Store per-benchmark results as dict: {"groups": [{"name": ..., "metrics": [...], "average": ...}]}

       d. For overall aggregation:
          - Use existing EvaluationCategory weights (get_all_categories()).
          - For each QualityGroup:
            - Collect per-benchmark averages for this group across all benchmarks.
            - Weight them by EvaluationCategory: find which category each benchmark belongs to, multiply benchmark's group average by category weight.
            - Sum weighted scores, divide by sum of weights (only for benchmarks that have non-None group average).
          - Store overall results in same structure.

       e. Return dict: {"overall": {"groups": [...]}, "by_benchmark": {"B1": {"groups": [...]}, "B2": {...}, ...}}

    3. In `_generate_summary`, after computing `by_benchmark` and `by_difficulty`:
       - Call: `quality_categories = self._aggregate_quality_categories(results, by_benchmark_raw)` where by_benchmark_raw uses short_name keys.
         - NOTE: by_benchmark currently uses result.test_case.benchmark_type.value (full name like "B1_CCoP_Applicability_Scope"). We need short_name grouping for quality_categories. Create a local grouping by short_name (result.test_case.benchmark_type.short_name).
       - Set: the returned dict on the summary DTO: pass it as `quality_categories=quality_categories` to EvaluationSummaryDTO constructor.

    4. Also update `_build_evaluation_metadata` to include quality_categories in metadata:
       ```python
       if summary.quality_categories:
           metadata["quality_categories"] = summary.quality_categories
       ```

    Important constraints:
    - Do NOT change existing _calculate_category_weighted_score logic -- overall_score computation stays identical.
    - Do NOT change _group_by_benchmark or _group_by_difficulty -- those remain backward compatible.
    - The quality_categories is ADDITIONAL data alongside existing structures.
  </action>
