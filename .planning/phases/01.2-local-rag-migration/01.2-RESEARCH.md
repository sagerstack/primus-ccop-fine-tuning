# Phase 1.2: Local RAG Migration - Research

**Researched:** 2026-03-01
**Domain:** Vector database migration (Databricks → Qdrant), local embedding generation (sentence-transformers), port/adapter pattern for swappable vector stores
**Confidence:** HIGH

## Summary

This phase migrates RAG infrastructure from Databricks (Mosaic AI Vector Search + managed BGE embeddings) to a fully local stack (Qdrant + sentence-transformers BGE-large-en-v1.5) using port/adapter pattern for swappable implementations. The migration preserves embedding consistency (same BGE model), hybrid search capabilities (dense + sparse RRF), and existing LangGraph pipeline behavior.

Key findings:
1. Qdrant provides native hybrid search with dense + sparse vectors via prefetch and RRF fusion, directly mapping to current Databricks RRF-based approach
2. sentence-transformers with BAAI/bge-large-en-v1.5 runs locally on Mac with automatic MPS backend selection, preserving exact embedding space from Databricks
3. FastEmbed with "Qdrant/bm25" model provides drop-in sparse vector generation for hybrid search
4. Port/adapter pattern with lazy DI factory pattern (already used for RAG pipeline) extends naturally to vector store and indexer abstractions
5. Docker Compose provides simple local Qdrant deployment with persistent storage

**Primary recommendation:** Use Qdrant native hybrid search with FastEmbed for BM25 sparse vectors, sentence-transformers for dense embeddings, and extend existing lazy DI pattern to support swappable vector store/indexer adapters.

### Pattern 1: Port/Adapter for Vector Store

**What:** Define abstract IVectorStore port in domain layer, implement concrete adapters (QdrantAdapter, DatabricksAdapter) in infrastructure.

**When to use:** When infrastructure components need to be swappable without changing core application logic.

**Example:**
```python
# Source: Hexagonal Architecture pattern adapted to vector store
# Domain layer (rag/domain/ports/i_vector_store.py)
from abc import ABC, abstractmethod
from typing import List, Dict, Any

class IVectorStore(ABC):
    """Port for vector store operations (retrieval only)."""

    @abstractmethod
    def similarity_search_with_scores(
        self,
        query: str,
        k: int = 10,
        filter: Optional[Dict[str, Any]] = None
    ) -> List[tuple[Document, float]]:
        """
        Search for similar documents with relevance scores.

        Args:
            query: Query text
            k: Number of results to return
            filter: Optional metadata filters

        Returns:
            List of (document, similarity_score) tuples
        """
        pass

# Infrastructure layer (rag/infrastructure/adapters/qdrant/qdrant_vector_store_adapter.py)
from qdrant_client import QdrantClient
from qdrant_client.models import Filter, FieldCondition, MatchValue

class QdrantVectorStoreAdapter(IVectorStore):
    """Qdrant implementation of IVectorStore."""

    def __init__(self, client: QdrantClient, collection_name: str, embedding_service):
        self.client = client
        self.collection_name = collection_name
        self.embedding_service = embedding_service

    def similarity_search_with_scores(
        self,
        query: str,
        k: int = 10,
        filter: Optional[Dict[str, Any]] = None
    ) -> List[tuple[Document, float]]:
        # Generate dense embedding
        dense_vector = self.embedding_service.embed_query(query)

        # Generate sparse embedding
        sparse_vector = self.embedding_service.embed_sparse(query)

        # Hybrid search with prefetch + RRF
        results = self.client.query_points(
            collection_name=self.collection_name,
            prefetch=[
                # Dense vector search
                {"query": dense_vector, "using": "dense", "limit": k * 2},
                # Sparse vector search
                {"query": sparse_vector, "using": "sparse", "limit": k * 2}
            ],
            query={"fusion": "rrf"},  # Reciprocal Rank Fusion
            limit=k,
            query_filter=self._build_filter(filter) if filter else None
        )

        # Convert to LangChain Document format
        return [(self._to_document(hit), hit.score) for hit in results.points]
```

### Pattern 2: Lazy Initialization with DI Factory

**What:** Use staticmethod factory pattern in DI container to defer imports and construction until first use, breaking circular dependencies.

**When to use:** When modules have circular import dependencies (Settings → Container → RAG modules → Settings).

**Example:**
```python
# Source: Existing pattern from src/infrastructure/config/container.py (lines 117-135)
from dependency_injector import containers, providers

class Container(containers.DeclarativeContainer):
    config = providers.Singleton(get_settings)
    logger = providers.Selector(...)

    # Factory function for lazy RAG adapter creation
    @staticmethod
    def _create_vector_store_adapter(settings, logger):
        """Lazy factory for vector store adapter selection."""
        # Import deferred until first call
        if settings.qdrant_url:  # Local Qdrant config present
            from rag.infrastructure.adapters.qdrant.qdrant_vector_store_adapter import (
                QdrantVectorStoreAdapter
            )
            from qdrant_client import QdrantClient

            client = QdrantClient(url=settings.qdrant_url)
            return QdrantVectorStoreAdapter(
                client=client,
                collection_name=settings.qdrant_collection_name,
                embedding_service=embedding_service
            )
        elif settings.databricks_host:  # Databricks config present
            from rag.infrastructure.adapters.databricks.databricks_vector_store_adapter import (
                DatabricksVectorStoreAdapter
            )
            return DatabricksVectorStoreAdapter(settings=settings)
        else:
            raise ValueError("No vector store configured (Qdrant or Databricks)")

    # Provider uses staticmethod
    vector_store = providers.Singleton(
        _create_vector_store_adapter,
        settings=config,
        logger=logger
    )
```

### Pattern 3: Embedding Service Abstraction

**What:** Wrap sentence-transformers and FastEmbed behind a service layer for both dense and sparse embedding generation.

**When to use:** When you need to generate both dense and sparse embeddings consistently across indexing and retrieval.

**Example:**
```python
# Source: Combined from sentence-transformers and FastEmbed documentation
from sentence_transformers import SentenceTransformer
from fastembed import SparseTextEmbedding

class EmbeddingService:
    """Service for generating dense and sparse embeddings locally."""

    def __init__(
        self,
        dense_model_name: str = "BAAI/bge-large-en-v1.5",
        sparse_model_name: str = "Qdrant/bm25",
        device: str = "auto"  # auto-selects MPS/CUDA/CPU
    ):
        # Dense embeddings via sentence-transformers
        self.dense_model = SentenceTransformer(dense_model_name, device=device)

        # Sparse embeddings via FastEmbed
        self.sparse_model = SparseTextEmbedding(model_name=sparse_model_name)

    def embed_query(self, text: str) -> List[float]:
        """Generate dense embedding for query."""
        # BGE models perform best with this prompt for retrieval
        prompt = "Represent this sentence for searching relevant passages: "
        return self.dense_model.encode(prompt + text).tolist()

    def embed_documents(self, texts: List[str]) -> List[List[float]]:
        """Generate dense embeddings for documents (batch)."""
        # Documents don't need query prompt
        return self.dense_model.encode(
            texts,
            batch_size=32,
            show_progress_bar=True,
            normalize_embeddings=True  # For cosine similarity
        ).tolist()

    def embed_sparse(self, text: str) -> Dict[str, Any]:
        """Generate sparse embedding (BM25) for query or document."""
        sparse_embeddings = list(self.sparse_model.embed([text]))
        sparse_emb = sparse_embeddings[0]

        # Convert to Qdrant sparse vector format
        return {
            "indices": sparse_emb.indices.tolist(),
            "values": sparse_emb.values.tolist()
        }
```

### Pattern 4: Qdrant Hybrid Search with Prefetch

**What:** Use Qdrant's prefetch mechanism to perform dense and sparse searches in parallel, then fuse with RRF.

**When to use:** When implementing hybrid search that combines semantic (dense) and keyword (sparse) retrieval.

**Example:**
```python
# Source: https://qdrant.tech/documentation/concepts/hybrid-queries
from qdrant_client import QdrantClient
from qdrant_client.models import PointStruct, VectorParams, Distance

client = QdrantClient(url="http://localhost:6333")

# Create collection with both dense and sparse vectors
client.create_collection(
    collection_name="ccop_clauses",
    vectors_config={
        "dense": VectorParams(
            size=1024,  # bge-large-en-v1.5 dimension
            distance=Distance.COSINE
        )
    },
    sparse_vectors_config={
        "sparse": {
            "modifier": "idf"  # Qdrant applies IDF automatically
        }
    }
)

# Query with hybrid search (prefetch + RRF)
results = client.query_points(
    collection_name="ccop_clauses",
    prefetch=[
        {
            "query": dense_embedding,  # List[float] from sentence-transformers
            "using": "dense",
            "limit": 20
        },
        {
            "query": {
                "indices": sparse_indices,  # From FastEmbed BM25
                "values": sparse_values
            },
            "using": "sparse",
            "limit": 20
        }
    ],
    query={"fusion": "rrf"},  # Reciprocal Rank Fusion
    limit=10,
    with_payload=True  # Include metadata
)
```

### Anti-Patterns to Avoid

- **Embedding Model Mismatch:** Using different embedding models for indexing vs retrieval breaks semantic consistency. CRITICAL: Use BAAI/bge-large-en-v1.5 for both indexing and queries (same as Databricks).

- **Missing Metadata in Vector Store:** Storing only vectors without metadata (document_source, section, clause, citation_id) prevents filtering and citation resolution. Migrate all metadata fields from Databricks schema.

- **Direct Client Usage in Application Layer:** Don't import QdrantClient directly in retrieval nodes. Use IVectorStore port abstraction to maintain swappability.

- **Ignoring Device Selection:** Not specifying device for sentence-transformers can result in slower CPU inference on Mac when MPS is available. Use `device="auto"` or explicit `device="mps"` for Apple Silicon.

- **Sparse Vector IDF Misconfiguration:** FastEmbed BM25 outputs raw term frequencies. Qdrant collection MUST have `modifier: "idf"` in sparse_vectors_config to apply IDF weighting server-side.

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Sparse vector generation from text | Custom TF-IDF or BM25 implementation | FastEmbed with "Qdrant/bm25" model | FastEmbed handles tokenization, IDF calculation, and Qdrant-compatible sparse format. Custom BM25 requires vocabulary management, IDF tracking across corpus, and format conversion. |
| Embedding model device management | Manual CUDA/MPS/CPU detection | sentence-transformers with `device="auto"` | Library automatically detects and uses strongest available backend (CUDA > MPS > CPU). Manual detection is error-prone across different hardware. |
| Hybrid search fusion | Custom score normalization + weighted combination | Qdrant native RRF via prefetch + query API | RRF is rank-based (doesn't require score normalization), handles incompatible score ranges. Custom fusion requires tuning weights, dealing with different score distributions. |
| Vector store connection pooling | Custom connection management | QdrantClient's built-in connection pooling | Client handles connection reuse, timeouts, retries. Custom pooling risks connection leaks and thread safety issues. |
| Batch embedding with progress | Manual batching + print statements | sentence-transformers `encode()` with `batch_size` and `show_progress_bar=True` | Built-in efficient batching with GPU memory management and rich progress display. Manual batching risks OOM errors. |

**Key insight:** Vector database and embedding libraries have matured significantly. The "simple" problems (BM25, batching, device selection) have edge cases (vocabulary consistency, memory management, hardware detection) that are solved by standard libraries.

## Common Pitfalls

### Pitfall 1: Embedding Drift After Migration

**What goes wrong:** Re-indexing with a different embedding model (even same architecture) causes embedding space mismatch between old and new vectors, degrading retrieval accuracy.

**Why it happens:** Embedding models have training-dependent initialization. Even same model name from different sources can produce different embeddings.

**How to avoid:**
- Use EXACT same model: `BAAI/bge-large-en-v1.5` (matches Databricks managed endpoint)
- Verify embedding dimension: 1024 (not 768 or 384 from other BGE variants)
- Test with known query-document pairs before full migration
- Consider re-ingesting entire corpus to ensure consistency (safe approach)

**Warning signs:**
- Similarity scores significantly lower post-migration for known relevant documents
- Previously working test queries return wrong documents
- Embedding dimension mismatch errors

### Pitfall 2: Missing Metadata Filter Translation

**What goes wrong:** Databricks and Qdrant use different metadata filtering syntax. Direct filter copy causes errors or returns empty results.

**Why it happens:** Databricks uses SQL-like filters, Qdrant uses JSON-based Filter/FieldCondition objects.

**How to avoid:**
```python
# Databricks (SQL-based): "document_source = 'CCoP 2.0' AND section = '5.5.2'"
# Qdrant (model-based):
from qdrant_client.models import Filter, FieldCondition, MatchValue

filter = Filter(
    must=[
        FieldCondition(key="document_source", match=MatchValue(value="CCoP 2.0")),
        FieldCondition(key="section", match=MatchValue(value="5.5.2"))
    ]
)
```

**Warning signs:**
- Filtered queries return 0 results when unfiltered queries work
- TypeError or validation errors when passing filters
- Different result counts between Databricks and Qdrant with same filter intent

### Pitfall 3: Lazy Initialization Race Conditions

**What goes wrong:** Multiple threads/requests call lazy initialization simultaneously, creating multiple client instances or incomplete initialization states.

**Why it happens:** Python's lazy initialization pattern without thread safety allows race conditions.

**How to avoid:**
```python
import threading

class QdrantVectorStoreAdapter:
    _lock = threading.Lock()
    _initialized = False

    def _ensure_initialized(self):
        if self._initialized:
            return

        with self._lock:  # Thread-safe initialization
            if self._initialized:  # Double-checked locking
                return

            self.client = QdrantClient(...)
            self._initialized = True
```

**Warning signs:**
- Intermittent "client not initialized" errors under load
- Multiple "initializing vector store" log entries
- Connection pool exhaustion

### Pitfall 4: Qdrant Collection Not Persisted

**What goes wrong:** Docker container restart wipes all indexed vectors because volume mount missing.

**Why it happens:** Default Qdrant Docker runs with in-memory storage if no volume specified.

**How to avoid:**
```yaml
# docker-compose.yml
services:
  qdrant:
    image: qdrant/qdrant:latest
    ports:
      - "6333:6333"
      - "6334:6334"
    volumes:
      - ./qdrant_storage:/qdrant/storage  # CRITICAL: Persistent storage
```

**Warning signs:**
- Index works fine but disappears after `docker compose down`
- Re-indexing required after every restart
- Collection exists but has 0 vectors after restart

### Pitfall 5: BM25 Sparse Vectors Without IDF Modifier

**What goes wrong:** Sparse vectors stored without IDF modifier produce incorrect similarity scores, degrading hybrid search quality.

**Why it happens:** FastEmbed BM25 outputs raw term frequencies. Qdrant applies IDF weighting only if collection configured with `modifier: "idf"`.

**How to avoid:**
```python
# When creating collection
sparse_vectors_config={
    "sparse": {
        "modifier": "idf"  # REQUIRED for BM25 semantics
    }
}

# NOT: sparse_vectors_config={"sparse": {}}  # Missing IDF
```

**Warning signs:**
- Hybrid search performs worse than dense-only
- Common terms (stopwords) rank too highly in sparse results
- RRF fusion doesn't improve over single-vector search

### Indexing CCoP Chunks with Dense + Sparse Vectors

```python
# Source: Combined from qdrant-client docs and sentence-transformers docs
from qdrant_client import QdrantClient
from qdrant_client.models import PointStruct
from sentence_transformers import SentenceTransformer
from fastembed import SparseTextEmbedding

# Initialize embedding models
dense_model = SentenceTransformer("BAAI/bge-large-en-v1.5")
sparse_model = SparseTextEmbedding(model_name="Qdrant/bm25")

# Example CCoP chunk
chunks = [
    {
        "id": "ccop-2.0.5.5.2.1",
        "text": "CII owners shall implement MFA for all privileged accounts...",
        "metadata": {
            "document_source": "CCoP 2.0",
            "section": "5.5.2 Access Control",
            "clause": "5.5.2.1",
            "citation_id": "CCoP-2.0.5.5.2.1",
            "document_type": "primary"
        }
    }
]

# Generate embeddings (batch for efficiency)
texts = [c["text"] for c in chunks]
dense_embeddings = dense_model.encode(texts, batch_size=32, normalize_embeddings=True)
sparse_embeddings = list(sparse_model.embed(texts))

# Prepare points for Qdrant
points = []
for i, chunk in enumerate(chunks):
    points.append(
        PointStruct(
            id=chunk["id"],  # String ID supported
            vector={
                "dense": dense_embeddings[i].tolist(),
                "sparse": {
                    "indices": sparse_embeddings[i].indices.tolist(),
                    "values": sparse_embeddings[i].values.tolist()
                }
            },
            payload=chunk["metadata"]  # Metadata for filtering and citation
        )
    )

# Upload to Qdrant
client.upsert(
    collection_name="ccop_clauses_hybrid",
    points=points,
    wait=True
)
```

### Hybrid Search with Metadata Filtering

```python
# Source: https://qdrant.tech/documentation/concepts/hybrid-queries
from qdrant_client import QdrantClient
from qdrant_client.models import Filter, FieldCondition, MatchValue

client = QdrantClient(url="http://localhost:6333")

# Query: "What are the MFA requirements?"
query_text = "What are the MFA requirements?"

# Generate query embeddings
dense_query = dense_model.encode(
    "Represent this sentence for searching relevant passages: " + query_text
).tolist()

sparse_query_emb = list(sparse_model.embed([query_text]))[0]
sparse_query = {
    "indices": sparse_query_emb.indices.tolist(),
    "values": sparse_query_emb.values.tolist()
}

# Hybrid search with filter for primary documents only
results = client.query_points(
    collection_name="ccop_clauses_hybrid",
    prefetch=[
        {"query": dense_query, "using": "dense", "limit": 20},
        {"query": sparse_query, "using": "sparse", "limit": 20}
    ],
    query={"fusion": "rrf"},  # Reciprocal Rank Fusion
    limit=10,
    query_filter=Filter(
        must=[
            FieldCondition(
                key="document_type",
                match=MatchValue(value="primary")
            )
        ]
    ),
    with_payload=True,
    with_vectors=False  # Don't return vectors, only metadata
)

# Results contain scored points with payload
for point in results.points:
    print(f"Score: {point.score}, Citation: {point.payload['citation_id']}")
    print(f"Text: {point.payload.get('text', 'N/A')[:100]}...")
```

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Manual BM25 implementation | FastEmbed "Qdrant/bm25" model | 2024-2025 | Eliminates custom tokenization, IDF management. Drop-in BM25 sparse vectors. |
| Separate dense + sparse indexes | Qdrant unified collection with prefetch | Qdrant 1.10 (2024) | Single collection, automatic RRF fusion via Query API. Simpler architecture. |
| LangChain VectorStore abstraction | Native Qdrant client with Query API | 2025-2026 | More control over prefetch/fusion parameters. LangChain wrapper lags behind Qdrant features. |
| sentence-transformers CPU-only | Automatic MPS backend for Apple Silicon | sentence-transformers 2.3+ (2023) | 5-10x speedup on Mac with M1/M2/M3 chips via GPU acceleration. |
| Manual embedding batching | Built-in batch encoding with progress bars | sentence-transformers 2.0+ | Efficient GPU memory usage, automatic progress tracking. |

**Deprecated/outdated:**
- **Qdrant "scroll" API for retrieval**: Replaced by Query API with prefetch (more efficient, supports hybrid search)
- **LangChain Qdrant class from community package**: Migrated to `langchain-qdrant` partner package (better maintained)
- **Manual RRF fusion**: Qdrant native `{"fusion": "rrf"}` replaces custom score combination code

## Open Questions

Things that couldn't be fully resolved:

1. **Optimal HNSW parameters for CCoP corpus (~1000 chunks)**
   - What we know: Qdrant defaults (m=16, ef_construct=100) work for most datasets
   - What's unclear: Whether smaller corpus benefits from tuned parameters (lower m, ef_construct)
   - Recommendation: Start with defaults, profile query latency. Re-index with adjusted params only if >100ms p95 latency.

2. **Re-ingestion vs embedding migration**
   - What we know: Same BGE model means embeddings should be identical
   - What's unclear: Whether to re-ingest from PDFs or export/import embeddings from Databricks
   - Recommendation: Re-ingest from PDFs (simpler, safer, verifies full pipeline). ~1000 chunks take <5 minutes to embed locally.

3. **Sparse vector model choice: BM25 vs SPLADE**
   - What we know: FastEmbed BM25 is simpler, SPLADE offers term expansion
   - What's unclear: Whether term expansion benefits CCoP regulatory text (formal, precise language)
   - Recommendation: Start with BM25 (matches Databricks approach). Evaluate SPLADE in future experiment if hybrid search underperforms.

4. **Collection deletion strategy for re-indexing**
   - What we know: Qdrant supports collection versioning and aliases
   - What's unclear: Whether to delete+recreate or use collection aliases for zero-downtime re-indexing
   - Recommendation: For local dev, delete+recreate is simpler. For production, implement blue/green with aliases.
