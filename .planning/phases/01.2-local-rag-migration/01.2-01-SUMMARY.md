# Phase 01.2 Plan 01: Local RAG Migration Foundation - Summary

**One-liner:** Domain ports (IVectorStore, IIndexer), EmbeddingService for BGE + BM25, Qdrant Docker setup, and Settings configuration

## What Was Built

### Port Interfaces (Domain Layer)
Created abstract port interfaces for vector store operations, establishing contracts for swappable implementations:

**IVectorStore** (`src/rag/domain/ports/i_vector_store.py`):
- `similarity_search_with_scores(query, k, filter)` - Retrieval contract
- Returns `List[tuple[Document, float]]` (LangChain Document type acceptable in ports)
- No infrastructure imports - domain purity maintained

**IIndexer** (`src/rag/domain/ports/i_indexer.py`):
- `index_chunks(chunks)` - Indexing contract
- `verify_index(index_name, sample_query)` - Verification contract
- Uses `CcopChunk` domain model
- No infrastructure imports

### EmbeddingService (Infrastructure Layer)
Local embedding generation replacing Databricks managed BGE endpoint:

**Dense embeddings:**
- BAAI/bge-large-en-v1.5 via sentence-transformers
- 1024 dimensions, normalized for COSINE distance
- BGE query prompt for queries: "Represent this sentence for searching relevant passages: "
- No prompt for documents (per BGE model documentation)

**Sparse embeddings:**
- FastEmbed BM25 via Qdrant/bm25 model
- Returns Qdrant-compatible sparse vector format (indices, values)

**Implementation patterns:**
- Lazy initialization - models loaded on first use (not on import)
- Thread-safe double-checked locking
- Batch processing with progress bars (`batch_size=32`, `show_progress_bar=True`)
- Device auto-selection (`device="auto"`) for MPS/CUDA/CPU

### Qdrant Docker Deployment
Docker Compose configuration for local Qdrant:

- Image: `qdrant/qdrant:latest`
- Ports: 6333 (REST API), 6334 (gRPC API)
- Volume: `./qdrant_storage` for persistent storage
- Health check: curl to `/healthz` every 30s
- Auto-restart: `unless-stopped`

### Settings Configuration
Extended Settings model with 4 Qdrant configuration fields:

- `qdrant_url: Optional[str]` - Default: None
- `qdrant_collection_name: Optional[str]` - Default: None
- `qdrant_embedding_model: Optional[str]` - Default: None
- `qdrant_sparse_model: Optional[str]` - Default: None

All use `CCOP_` env prefix (consistent with existing pattern).

Added Qdrant config section to `.env.example` and `.env.local`:

## Technical Decisions

### 1. Port Method Signatures
**Decision:** `similarity_search_with_scores()` returns `List[tuple[Document, float]]`

**Rationale:**
- Document is a data type from langchain_core, acceptable in ports (not infrastructure code)
- Both Qdrant and Databricks adapters can convert to this format
- Matches existing LangGraph pipeline expectations

**Alternatives considered:**
- Custom domain document type (overengineering for current needs)
- Raw dict format (loses type safety)

### 2. Lazy Model Initialization
**Decision:** EmbeddingService loads models on first use, not in `__init__`

**Rationale:**
- BGE model is 1.3GB+ - avoid loading during import or dry-run modes
- Supports Settings instantiation without embedding dependencies installed
- Enables graceful degradation when RAG config absent

**Implementation:**
- Thread-safe double-checked locking pattern
- Separate locks for dense and sparse models
- `_ensure_dense_model()` and `_ensure_sparse_model()` private methods

### 3. BGE Query Prompt Application
**Decision:** Apply query prompt only in `embed_query()`, not `embed_documents()`

**Evidence:**
- BGE model card specifies query prompt improves retrieval
- Research shows prompt degrades document embeddings
- Plan explicitly flagged this as anti-pattern to avoid

**Implementation:**
```python
# embed_query: Add prompt
prompt = "Represent this sentence for searching relevant passages: "
embedding = model.encode(prompt + text, ...)

# embed_documents: No prompt
embeddings = model.encode(texts, ...)
```

### 4. Normalization for COSINE Distance
**Decision:** All dense embeddings normalized (`normalize_embeddings=True`)

**Rationale:**
- Qdrant collection will use COSINE distance (plan 02)
- Normalized embeddings required for correct COSINE similarity
- sentence-transformers handles normalization efficiently

## Known Limitations

1. **Docker Compose not tested:** Docker daemon not running during execution. Structure correct but startup/health check not verified.

2. **Embedding dimension hardcoded:** `embedding_dimension` property returns 1024 (bge-large-en-v1.5 dimension). If model changes, property must be updated. Could introspect model on first load.

3. **No embedding cache:** Every call to `embed_query()` or `embed_documents()` runs inference. For repeated queries, consider adding LRU cache in future optimization.

4. **FastEmbed version constraint:** `>=0.4.0` allows breaking changes. Consider pinning to `^0.4.0` after testing.

## Lessons Learned

### What Worked Well
1. **Port abstraction first:** Defining contracts before implementations enables parallel work on adapters
2. **Lazy initialization pattern:** Already established in existing codebase (Container), reused successfully
3. **Thread-safe double-checked locking:** Clean pattern for lazy init without race conditions

### What Could Improve
1. **Docker verification:** Could add Docker Desktop startup check, but acceptable to defer to integration testing
2. **Dependency installation timing:** Could have installed dependencies before writing EmbeddingService (minor)

### Reusable Patterns
1. **Port definition template:** ABC with abstractmethod, clear docstrings, type hints
2. **Service layer pattern:** Wrapping external libraries (sentence-transformers, fastembed) behind clean interface
3. **Settings expansion pattern:** Optional fields with env prefix, clear descriptions
