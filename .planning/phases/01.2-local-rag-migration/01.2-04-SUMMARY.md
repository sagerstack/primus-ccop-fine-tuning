## Decisions Made

**Container lazy factories for adapter selection**
- Container creates vector_store and indexer providers using lazy staticmethod factories
- Selection logic: Qdrant (if qdrant_url set) > Databricks (if databricks_host set) > None
- Lazy imports maintain circular dependency protection pattern established in Plan 01
- EmbeddingService created inside factory (not separate provider) to avoid loading 1.3GB+ models when using Databricks

**Ingestion uses factory instead of container**
- Ingestion orchestrator creates indexer via _create_indexer factory function (not container.indexer())
- Rationale: Ingestion is a batch script (not part of API runtime), simpler to create directly
- Same selection logic as container factories

**Graceful handling of missing backends**
- Container returns None when neither Qdrant nor Databricks configured
- Retrieval node logs error and sets empty documents when vector_store is None
- Ingestion orchestrator raises ValueError with helpful message listing required config
