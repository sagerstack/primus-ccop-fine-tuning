## Decisions Made

**DatabricksVectorStoreAdapter design:**
- Extracts retriever initialization logic from `src/rag/retrieval/nodes/retrieval.py` lines 23-81
- Same config validation (host, token, endpoint)
- Same env var bridging (DATABRICKS_HOST, DATABRICKS_TOKEN)
- Same index naming pattern (`{catalog}.{schema}.ccop_clauses_hybrid`)
- Filter parameter accepted but logged as warning (Databricks uses index config for filtering)

**DatabricksIndexerAdapter design:**
- Very thin wrapper - almost pure delegation to existing DatabricksIndexer
- DatabricksIndexer already validates config, no duplication needed
- Lazy import from rag.ingestion.indexers.databricks_indexer to avoid circular dependencies

**Lazy initialization pattern:**
- Both adapters store settings in __init__ but don't create clients
- _ensure_initialized() called on first operation (similarity_search_with_scores or index_chunks)
- Enables dry-run mode without Databricks credentials
- Same pattern as QdrantVectorStoreAdapter from Plan 01.2-01
