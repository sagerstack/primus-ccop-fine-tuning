# Phase 2.4 Plan 01: Universal Judge Domain Model Summary

Universal judge evaluation infrastructure with combined hallucination detection and reasoning depth scoring in a single Claude call.

## One-liner

Extended JudgeEvaluation with hallucination fields and created universal_evaluate_response with question-adaptive two-dimension evaluation prompt.

## What Was Built

### 1. JudgeEvaluation Model Extensions

**New fields for universal judge evaluation:**
- `hallucination_detected: bool` - Binary gate for hallucination verdict
- `unsupported_count: int` - Count of UNSUPPORTED claims
- `contradicted_count: int` - Count of CONTRADICTED claims
- `claims: List[Dict[str, str]]` - Claim-level verification results with text, status, evidence
- `reasoning_criteria_met: Dict[str, Optional[bool]]` - Question-adaptive criteria evaluation (True/False/None)

**from_universal_judge factory method:**
- Computes overall_score with hallucination gate: 0.0 if hallucination_detected, else reasoning_depth_score / 3.0
- reasoning_depth_score = count of True values in reasoning_criteria_met (excluding None/N/A)
- Creates single DimensionScore with name="reasoning_depth"

**Backward compatibility:**
- Existing from_dimensions and error factories unchanged
- New fields have sensible defaults (False, 0, empty lists/dicts)
- Rubric-based evaluation path unaffected

### 2. Response Extractor Utility

**Created domain.services.response_extractor module:**
- `extract_final_answer(response_text: str) -> str` - Extracts content after "Final Answer:" marker
- Handles case-insensitive variations ("Final Answer:", "FINAL ANSWER:", "final answer:")
- Returns full response if no marker found (model may not use chain-of-thought)
- Pure function with no dependencies beyond `re` module

**Purpose:**
- Llama-Primus-Reasoning generates chain-of-thought output before final answer
- Judge should evaluate only the final answer, not the reasoning steps
- Prevents judge from being influenced by model's internal reasoning

### 3. Universal Judge Evaluation Method

**UNIVERSAL_JUDGE_PROMPT class constant:**

Combined two-dimension evaluation in a single prompt:

**PART 1 - Hallucination Check:**
- Extract atomic claims from response
- Verify each claim against retrieved contexts
- Status: SUPPORTED / UNSUPPORTED / CONTRADICTED
- Explicit instruction: "Valid inference is NOT hallucination" (prevents false positives)
- Verdict: hallucination_detected = any UNSUPPORTED or CONTRADICTED

**PART 2 - Reasoning Depth (question-adaptive):**
- Evaluate 3 criteria for applicability first, then score:
  - `clause_citations`: References specific CCoP clauses? (applicable for most questions)
  - `conditional_analysis`: Analyzes if-then scenarios? (N/A for pure factual lookup)
  - `actionable_steps`: Provides concrete CIIO steps? (N/A for classification questions)
- Use null for N/A criteria
- reasoning_depth_score = count of criteria marked true (0-3)

**JSON output format:**
```json
{
  "claims": [{"text": "...", "status": "...", "evidence": "..."}],
  "hallucination_detected": true/false,
  "unsupported_count": N,
  "contradicted_count": M,
  "reasoning_depth_score": 0-3,
  "reasoning_criteria_met": {
    "clause_citations": true/false/null,
    "conditional_analysis": true/false/null,
    "actionable_steps": true/false/null
  },
  "justification": "...",
  "confidence": 0.0-1.0
}
```

**universal_evaluate_response method:**
- Signature: `universal_evaluate_response(test_case, response, benchmark_id, retrieved_contexts=None)`
- Extracts final answer via `extract_final_answer(response.content)`
- Formats UNIVERSAL_JUDGE_PROMPT with question, final_answer, contexts
- Calls Claude judge via existing `_call_claude_agent`
- Parses response via `_parse_universal_judge_response`
- Returns JudgeEvaluation via `from_universal_judge` factory
- Error handling: returns JudgeEvaluation.error on failure

**_parse_universal_judge_response parser:**
- Handles markdown code blocks (```json, ```)
- Extracts all universal judge fields from JSON
- Creates JudgeEvaluation via from_universal_judge factory
- Returns JudgeEvaluation.error on parse failure

## Technical Notes

### Hallucination Gate Design

The hallucination gate is strict by design:
- ANY unsupported or contradicted claim → overall_score = 0.0
- Reasoning depth is ignored when hallucination detected
- Rationale: CII organizations cannot use hallucinated compliance advice

### Question-Adaptive Criteria

The universal judge evaluates criteria applicability before scoring:
- Classification questions: clause_citations=T/F, conditional_analysis=null, actionable_steps=null
- Reasoning questions: all three criteria applicable
- Advisory questions: clause_citations=T/F, conditional_analysis=T/F, actionable_steps=T/F

This prevents penalizing responses for not including criteria that weren't applicable.

### Final Answer Extraction

The response extractor removes chain-of-thought reasoning before judge evaluation:
- Model: "Let me analyze... [500 words] Final Answer: The answer is X"
- Judge sees: "The answer is X"
- Prevents judge contamination by model's reasoning steps

### Error Handling

Both tasks follow skip-and-flag pattern:
- Parse failures → JudgeEvaluation.error with error_message
- Claude call failures → JudgeEvaluation.error with error_message
- Downstream systems check judge_error flag
