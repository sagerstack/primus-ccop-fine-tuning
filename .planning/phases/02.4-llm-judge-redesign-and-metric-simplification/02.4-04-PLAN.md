<objective>
Wire the judge_mode toggle through the full application stack: CLI flag -> DTO -> use case -> scoring service. Add shadow retrieval for universal+llm-only mode. Display judge criteria transparency in CLI. Persist new judge data in JSON schema v5.

Purpose: The universal judge and RAGAs formula changes from Plans 01-03 exist in the domain layer but aren't accessible to users yet. This plan wires them through the application, presentation, and infrastructure layers. Shadow retrieval enables hallucination detection in llm-only mode by retrieving contexts for the judge (not the model). The CLI displays which reasoning criteria were applicable and met, making the judge's decisions auditable.

Output: Full end-to-end judge_mode toggle, shadow retrieval, CLI criteria display, JSON schema v5.

**Implementation sequencing (6 files across 3 layers):**
1. Settings (infrastructure) — add CCOP_JUDGE_MODE config
2. DTOs (application) — add judge_mode to request, judge fields to result
3. Use case (application) — wire judge_mode through, add shadow retrieval
4. Scoring service (domain) — update _score_universal_judge metadata serialization
5. CLI (presentation) — add --judge-mode flag, criteria display, remove fct_prec column
6. JSON repository (infrastructure) — bump schema to v5, persist judge data

Task 1 covers steps 1-3. Task 2 covers steps 4-6. Execute tasks in order.
</objective>
