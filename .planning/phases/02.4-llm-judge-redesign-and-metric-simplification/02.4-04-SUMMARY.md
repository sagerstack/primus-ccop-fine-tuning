## Decisions Made

**Shadow retrieval implementation:**
In universal+llm-only mode, RAG pipeline queries for contexts using hybrid mode but only passes them to the judge (not to the model). This enables hallucination detection in llm-only mode without changing the model's input. Placed after model response but before scoring service call.

**Judge metadata serialization:**
_score_universal_judge serializes judge metadata (hallucination_detected, claims, reasoning_criteria_met, etc.) as JSON in EvaluationMetric.description field. Application layer (_result_to_dto) parses this JSON to populate DTO fields. Avoids modifying domain entity structure while propagating complex judge data through simple value objects.

**CLI criteria transparency format:**
Per-test-case panels show:
- Reasoning criteria (clause_citations, conditional_analysis, actionable_steps) as YES (green) / NO (red) / N/A (dim)
- Hallucination as YES (red) / NO (green) with claim counts (N claims: M unsupported, K contradicted)
Makes judge decisions auditable and transparent to users.

**JSON schema v5 structure:**
Test results include:
- `judge_mode`: "rubric" or "universal" (top-level field)
- `judge_evaluation`: Object with hallucination_detected, unsupported/contradicted counts, reasoning_depth_score (0-3), reasoning_criteria_met, claims, justification (only present when judge_mode="universal")
Backward compatible: rubric mode gets judge_mode="rubric" without judge_evaluation object.

**factual_precision removal:**
- Removed from flat benchmark table header (7 columns now: ctx_recall, ctx_precision, ctx_faith, fct_recl, ans_relev, sem_sim, LLM Judge)
- Removed from per-test-case RAGAs answer metrics display
- Removed from JSON response_quality group check (already absent from RAGAs service in Plan 03)
Cleaner metric set without redundancy with universal judge hallucination check.
