<objective>
Redesign the LLM Judge domain model and service to support two universal evaluation dimensions (reasoning depth + hallucination detection) alongside the existing per-benchmark rubric path.

Purpose: The current 15 per-benchmark rubrics evaluate different dimensions per benchmark. The new universal judge evaluates ALL LLM-judged benchmarks on the same two dimensions: (1) reasoning depth (clause citations + conditional analysis + actionable CIIO steps, 0-3 scale), and (2) hallucination detection (binary, claim-level verification against retrieved contexts). Both paths coexist for parallel comparison via a toggle.

Output: Updated JudgeEvaluation model with hallucination fields, universal combined prompt, final-answer extraction utility. The existing rubric-based path remains intact.
</objective>

    Add a new method `universal_evaluate_response` to LLMJudgeService that implements the combined two-dimension judge prompt.

    **Method signature:**
    ```python
    def universal_evaluate_response(
        self,
        test_case: TestCase,
        response: ModelResponse,
        benchmark_id: str,
        retrieved_contexts: Optional[List[str]] = None,
    ) -> JudgeEvaluation:
    ```

    **Combined prompt structure (store as class constant UNIVERSAL_JUDGE_PROMPT):**

    The prompt must:
    1. Instruct the judge to evaluate a CCoP 2.0 compliance response on two dimensions
    2. Provide: QUESTION, RESPONSE (extracted final answer only — call `extract_final_answer` on `response.content`), RETRIEVED CONTEXTS (joined text of retrieved_contexts list, or "No retrieved contexts available" if None/empty)
    3. PART 1 - HALLUCINATION CHECK:
       - Extract atomic claims from response
       - Verify each claim against RETRIEVED CONTEXTS — SUPPORTED/UNSUPPORTED/CONTRADICTED
       - Explicit instruction: "A claim citing a different clause than expected is SUPPORTED if that clause is factually correct per the contexts. Valid inference is NOT hallucination."
       - Verdict: hallucination_detected = any UNSUPPORTED or CONTRADICTED
    4. PART 2 - REASONING DEPTH (question-adaptive):
       - Evaluate which of 3 criteria are applicable to this question type:
         - clause_citations: Does response reference specific CCoP clauses? (applicable for most questions)
         - conditional_analysis: Does response analyze if-then scenarios? (applicable for reasoning questions, N/A for pure factual)
         - actionable_steps: Does response provide concrete CIIO implementation steps? (applicable for advisory questions, N/A for classification)
       - First determine which criteria are applicable, then score each applicable criterion as met or not met
    5. Output JSON format:
    ```json
    {
      "claims": [{"text": "...", "status": "SUPPORTED|UNSUPPORTED|CONTRADICTED", "evidence": "..."}],
      "hallucination_detected": true/false,
      "unsupported_count": N,
      "contradicted_count": M,
      "reasoning_depth_score": 0-3,
      "reasoning_criteria_met": {
        "clause_citations": true/false/null,
        "conditional_analysis": true/false/null,
        "actionable_steps": true/false/null
      },
      "justification": "...",
      "confidence": 0.0-1.0
    }
    ```
    Where null means the criterion was deemed not applicable for this question type.

    **Parsing:** Add `_parse_universal_judge_response(self, response: str) -> JudgeEvaluation` that:
    - Extracts JSON from response (reuse existing markdown code block stripping)
    - Creates JudgeEvaluation via `from_universal_judge` factory
    - On parse failure, returns JudgeEvaluation.error()

    **Error handling:** Same pattern as existing evaluate_response — wrap in try/except, return JudgeEvaluation.error on failure.

    **Important:** The existing `evaluate_response` method and `_build_judge_prompt` method must remain UNCHANGED. They are the "old" rubric-based path. The toggle between old and new happens in ScoringService (Plan 03), not here.

    **Import extract_final_answer** from domain.services.response_extractor at the top of the file.
  </action>
