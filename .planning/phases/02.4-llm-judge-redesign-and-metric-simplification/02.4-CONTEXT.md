# Phase 2.4: LLM Judge Redesign and Metric Simplification - Context

**Gathered:** 2026-03-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the 15 per-benchmark LLM Judge rubric dimensions with two universal dimensions (reasoning depth + hallucination check). Redesign the model's system prompt to align with the new evaluation criteria. Add a toggle to switch all benchmarks to the new LLM Judge scoring. Keep all RAGAs metrics as-is. <decisions>
## Implementation Decisions

### Reasoning Depth Scoring
- **Definition of deep reasoning**: Clause-specific citations + conditional analysis + concrete actionable steps for the CIIO
- **Definition of shallow reasoning**: Generic compliance advice without those layers
- **Scoring scale**: RESEARCH — investigate best practices for LLM-as-judge reasoning depth scoring (0-3, 0-5, binary, or other)
- **Question-adaptive criteria (LOCKED)**: The judge must determine which criteria are applicable based on the question type. A factual question (B1, B5) may only need clause citations (1 criterion), while a reasoning question (B3, B7-B10) needs all three (clause citations + conditional analysis + actionable steps). Score normalizes to 0-1 based on applicable criteria, not fixed out of 3. This prevents penalizing the model for question types that don't call for conditional analysis or CIIO steps.
- **Criteria transparency (LOCKED)**: The per-test-case CLI output must show which criteria the judge deemed applicable and whether each was met. Example: `clause_citations: YES | conditional_analysis: N/A | actionable_steps: YES`. This makes the judge's reasoning visible and auditable.
- **Judge evaluates final answer only (LOCKED)**: The model (Llama-Primus-Reasoning) produces chain-of-thought before "Final Answer:". Industry standard for reasoning models is to evaluate the extracted final answer, not the internal CoT. Post-process the response to extract content after "Final Answer:" before passing to the judge. This aligns with the existing bug fix (chain-of-thought displayed as raw response).
- **Reference-free vs reference-guided**: RESEARCH — investigate whether the judge should see the expected_response when scoring reasoning depth

### Hallucination Detection
- **Judge inputs**: RESEARCH — investigate optimal context passing (full retrieved chunks vs chunk citations vs summary)
- **Scoring approach**: RESEARCH — investigate binary pass/fail vs graded severity vs penalty multiplier
- **Hallucination severity taxonomy**: RESEARCH — investigate whether to distinguish 'wrong but plausible' from 'completely fabricated' in compliance domains
- **LLM-only mode**: RESEARCH — one option to investigate: retrieve chunks in LLM-only mode but only pass them to the judge (not the model). Model generates from own knowledge, judge checks claims against what RAG would have provided. Decouples retrieval-for-grounding from retrieval-for-evaluation
- **Retrieved context in judge prompt**: The judge must receive retrieved context to check hallucination — this is new (current judge only sees question, response, expected_response, rubric)

### RAGAs Metrics and Formula
- **Keep all RAGAs metrics as-is**: No metric additions or removals in this phase
- **Scoring formula**: RESEARCH — assess whether the multiplicative penalty formula (base * factual_precision) should change to complement the new LLM Judge dimensions
- **Combined vs independent scores**: RESEARCH — investigate whether a single unified score or independent Benchmark + RAGAs scores is more informative

### Per-Benchmark Rubric Migration
- **Existing rubrics file**: Keep `evaluation-rubrics.md` as reference (archived, not used in scoring)
- **Rule-based benchmarks B1-B6 stay rule-based**: RESEARCH — assess whether these benefit from LLM Judge (research recommends keeping them rule-based)
- **B21 migrates to LLM Judge via toggle (LOCKED)**: When new judge toggle is ON, B21 uses the LLM Judge hallucination detection instead of regex. When toggle is OFF, falls back to regex. Same toggle mechanism as all other benchmarks
- **Migration strategy**: Parallel run with toggle — both old (per-benchmark rubrics + rule-based) and new (universal reasoning + hallucination) scoring paths exist simultaneously, controlled by a toggle (e.g., CLI flag or config setting). Compare results, then switch
- **Toggle scope**: Switches ALL benchmarks to new LLM Judge scoring (not per-benchmark opt-in)

### Model System Prompt Redesign
- **Alignment principle**: The model's system prompt must instruct the model to produce what the judge scores for. If the judge scores clause citations + conditional analysis + actionable CIIO steps, the system prompt must guide the model to produce those
- **Current gap**: System prompt gives general CCoP instructions without specifying response structure expectations
- **Scope**: Redesign the RAG generation system prompt to explicitly guide the model toward producing responses with: (1) specific clause citations from retrieved context, (2) conditional analysis of the compliance scenario, (3) concrete actionable steps for the CIIO
- **Constraint**: System prompt changes apply to the generation node in the RAG pipeline — affects both hybrid and llm-only modes

<specifics>
## Specific Ideas

- The model's response to B3-001 introduced valid reasoning (individual accountability, shared account principles) that was penalized by factual_precision — this is the motivating example for the redesign
- context_faithfulness (0.80) gives an upper bound on hallucination but can't distinguish valid inference from fabrication — this gap is what the LLM Judge hallucination dimension should fill
- The key insight driving this phase: RAGAs handles factual quality (coverage, relevance, grounding), LLM Judge should handle what only an LLM can assess (reasoning quality, hallucination detection)

</specifics>
