# Phase 2.3 Plan 01: RAGAs Metric Split & Scoring Formula Summary

**One-liner:** Split answer_correctness into FactualCorrectness(precision/recall), add SemanticSimilarity diagnostic, implement multiplicative penalty formula (base * precision) in domain entity

## What Was Delivered

### Core Changes

1. **RagasEvaluationService metric restructure**
   - Replaced `_AnswerCorrectness()` with `FactualCorrectness(llm, mode="precision")` and `FactualCorrectness(llm, mode="recall")`
   - Added `SemanticSimilarity(embeddings)` as display-only diagnostic
   - Removed hallucination metric (faithfulness trick) — factual_precision replaces it
   - Reduced from 3 evaluate() calls to 2 (base + context, not base + halluc + context)

2. **Domain scoring formula**
   - Added `EvaluationResult.ragas_composite_score` property (single source of truth)
   - Formula: `base_score * factual_precision`
   - Base score: `(1/3)*factual_recall + (1/3)*factual_precision + (1/3)*answer_relevancy`
   - Quadratic penalty on low-precision responses: 0.2 precision → 0.11 score, 0.9 precision → 0.75 score

3. **Quality group updates**
   - Model Response Quality now contains: factual_precision, factual_recall, answer_relevancy, semantic_similarity, llm_judge
   - Removed: hallucination, answer_correctness
   - Updated display names mapping

4. **Application layer cleanup**
   - `_extract_ragas_score()` delegates to `result.ragas_composite_score` (thin wrapper)
   - Deleted `_calculate_combined_score()` method entirely
   - Removed `combined_score` from EvaluationResultDTO
   - Removed `combined_overall_score` from EvaluationSummaryDTO

### Metrics Produced

**Before (Phase 2.2):**
- answer_correctness (blended: 75% factual F1 + 25% semantic similarity)
- answer_relevancy
- hallucination (faithfulness vs ground truth)
- context_faithfulness (RAG only)
- context_precision (RAG only)
- context_recall (RAG only)

**After (Phase 2.3):**
- factual_precision (supported claims / total claims)
- factual_recall (covered facts / total ground truth facts)
- answer_relevancy (unchanged)
- semantic_similarity (display-only diagnostic)
- context_faithfulness (RAG only, unchanged)
- context_precision (RAG only, unchanged)
- context_recall (RAG only, unchanged)

## Lessons Learned

1. **Domain property pattern for derived metrics:** Centralizing formula logic in domain entity (ragas_composite_score) eliminates duplication and makes the application layer a thin orchestrator. Strong pattern for any derived metric.

2. **Multiplicative penalties create strong signals:** Linear averaging (old combined_score) muted differences. Multiplicative penalty (base * precision) creates dramatic score separation: hallucinating responses drop from 0.87 to 0.11.

3. **Display-only diagnostics:** semantic_similarity is useful for understanding model behavior but not a quality signal for scoring. Separating diagnostic metrics from scoring metrics prevents pollution of the composite score.

4. **Metric extraction robustness:** FactualCorrectness with mode="precision" and mode="recall" may produce varying key names depending on RAGAs version. Current string-based key matching ("factual" + "precision") is fragile. Inspecting metric objects or using metric.name would be more robust.
