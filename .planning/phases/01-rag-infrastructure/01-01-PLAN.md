  <action>
    1. Create `src/ingestion/parsers/ccop_pdf_parser.py`:
       - Function `parse_ccop_pdf(pdf_path: str, document_name: str) -> str` that:
         - Uses `pymupdf4llm.to_markdown(pdf_path, page_chunks=False, write_images=False)` to extract markdown with structure preservation
         - Returns raw markdown string
         - Logs document name, page count, and output length
       - Function `parse_all_ccop_documents(ccop_dir: str) -> dict[str, str]` that:
         - Iterates over all 8 known CCoP documents:
           * `CCoP---Second-Edition_Revision-One.pdf` -> "CCoP 2.0"
           * `RESPONSE-TO-FEEDBACK.pdf` -> "CCoP Response to Feedback"
           * `supplementary/Guidelines_for_Auditing_Critical_Information_Infrastructure.pdf` -> "Auditing Guidelines"
           * `supplementary/Guide-to-Cyber-Threat-Modelling.pdf` -> "Threat Modelling Guide"
           * `supplementary/Guide-to-Conducting-Cybersecurity-Risk-Assessment-for-CII.pdf` -> "Risk Assessment Guide"
           * `supplementary/Security_By_Design_Framework.pdf` -> "Security By Design"
           * `references/Ensign's_Cybersecurity_Guide_on_CCoP_2_0_for_CII_Sep_2022.pdf` -> "Ensign CCoP Guide"
           * `references/Cybersecurity Act 2018.pdf` -> "Cybersecurity Act 2018"
         - Returns dict mapping document_name -> markdown text
         - Document names and paths must NOT be hardcoded in source — store them in a configuration dataclass or load from a config file

    2. Create `src/ingestion/parsers/feedback_qa_parser.py`:
       - Function `parse_feedback_qa(markdown_text: str) -> list[QAPair]` that:
         - Takes the markdown output from RESPONSE-TO-FEEDBACK.pdf
         - Identifies Q&A pairs (questions and their responses)
         - Extracts linked CCoP clause references from each answer using regex pattern `r'\b(\d+\.\d+\.?\d*)\b'`
         - Returns list of QAPair objects with document_type="clarification" in metadata
       - The parser should handle the specific format of the RESPONSE-TO-FEEDBACK document (numbered questions with responses)
       - If clause linking fails (no clause found), set linked_clause to empty string and log a warning

    3. Create `src/ingestion/chunkers/section_chunker.py`:
       - Function `chunk_document(markdown_text: str, document_name: str) -> list[CcopChunk]` that:
         - Uses `MarkdownHeaderTextSplitter` from langchain with headers_to_split_on:
           * ("#", "Document")
           * ("##", "Section")
           * ("###", "Subsection")
         - Sets `strip_headers=False` to keep headers in chunks for context
         - Enriches each chunk with metadata:
           * document_source: the document_name parameter
           * section: from header metadata
           * subsection: from header metadata
           * clause: extracted via regex `r'\b(\d+\.\d+\.?\d*)\b'` from first 200 chars of chunk
           * citation_id: formatted as `"{document_name}.{section}.{clause}"` or `"{document_name}.{section}"` if no clause
         - Applies size constraints:
           * Minimum: 200 tokens (merge small chunks with preceding chunk)
           * Maximum: 1000 tokens (recursively split on paragraph boundaries if exceeded)
           * Token counting: use `len(text.split())` as approximation (no tokenizer dependency needed)
         - Returns list of CcopChunk objects with sequential IDs like `"{document_name}-{index}"`
       - Function `chunk_qa_pairs(qa_pairs: list[QAPair], document_name: str) -> list[CcopChunk]` that:
         - Converts QAPair objects into CcopChunk objects
         - Sets document_type="clarification" in metadata
         - Formats text as "Q: {question}\nA: {answer}"
       - Function `chunk_all_documents(parsed_docs: dict[str, str], ccop_dir: str) -> list[CcopChunk]` that:
         - Orchestrates parsing and chunking for all 8 documents
         - Uses feedback_qa_parser for RESPONSE-TO-FEEDBACK
         - Uses standard section chunking for all other documents
         - Returns combined list of all chunks
         - Logs total chunk count, per-document counts, and chunk size statistics

    AVOID: Do NOT use a tokenizer library for token counting — word count approximation is sufficient for chunking boundaries.
    AVOID: Do NOT add citation anchors to chunk text yet — that happens in Plan 04 (citations).
    WHY section-level chunking: Research shows 87.7% context recall vs ~65% for fixed-size chunking on structured regulatory documents. This is the highest-impact decision for retrieval quality.
