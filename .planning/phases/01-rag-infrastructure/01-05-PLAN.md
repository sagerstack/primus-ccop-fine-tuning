       - Test `extract_citation_ids`:
         * Single anchor: `"<c>CCoP 2.0.5.5.2.1</c>"` -> `["CCoP 2.0.5.5.2.1"]`
         * Multiple anchors: text with 3 anchors -> list of 3 IDs
         * No anchors: plain text -> empty list
         * Duplicate anchors: same ID twice -> single ID (deduplicated)
         * Nested/malformed anchors: handles gracefully

       - Test `resolve_citations`:
         * Valid resolution: citation_id matches document metadata -> returns resolved dict
         * Missing citation: ID not in documents -> skipped (no crash)
         * Empty documents list -> empty result
         * Multiple citations resolved correctly with all metadata fields

       - Test `format_response_with_citations`:
         * With citations: produces clean text + "References:" section
         * Anchor removal: `<c>...</c>` tags stripped from response text
         * No citations: returns text as-is, no "References:" section
         * Multiple citations numbered correctly [1], [2], [3]

       - Test `format_model_only_response`:
         * Prepends notice about model-only response
         * No references section

    3. Create `src/tests/rag/retrieval/test_graph_state.py`:
       - Test GraphState initialization with required fields
       - Test default values for optional fields
       - Test state can hold Document objects

    4. Create `src/tests/rag/ingestion/test_section_chunker.py`:
       - Test `chunk_document` with sample markdown:
         * Create a small sample markdown string with ## and ### headers
         * Verify chunks split at header boundaries
         * Verify metadata extraction (section, subsection, clause)
         * Verify citation_id format

       - Test size constraints:
         * Small section (< 200 tokens) merged with preceding chunk
         * Large section (> 1000 tokens) split on paragraph boundaries

       - Test `chunk_qa_pairs`:
         * QAPair converted to CcopChunk correctly
         * document_type="clarification" in metadata
         * Text formatted as "Q: ... A: ..."

       - Test clause extraction:
         * "Section 5.2.1 requires..." -> clause "5.2.1"
         * No clause number -> empty string

    5. Create `src/tests/rag/retrieval/test_retrieval_precision.py`:
       This test benchmarks retrieval precision against ground truth to verify Phase 1 Success Criterion 3.

       - Define 10 ground truth query-answer pairs as test fixtures. Each pair has:
         * `query` (str): A CCoP compliance question
         * `expected_sections` (list[str]): CCoP sections that MUST appear in retrieved results
         * `expected_documents` (list[str]): Source documents that MUST appear

       - Ground truth queries (derive from the CCoP document structure):
         * "What are the access control requirements for CII?" -> expects CCoP 2.0 Section 5
         * "What are the incident reporting timelines under CCoP?" -> expects CCoP 2.0 Section 7
         * "How should CII owners conduct cybersecurity risk assessment?" -> expects Risk Assessment Guide
         * "What are the requirements for cybersecurity audit of CII?" -> expects Auditing Guidelines
         * "What does CCoP say about threat modelling?" -> expects Threat Modelling Guide
         * "What are the physical security requirements for CII?" -> expects CCoP 2.0 Section 4
         * "How should CII owners implement security monitoring?" -> expects CCoP 2.0 Section 6
         * "What are the network security requirements?" -> expects CCoP 2.0 Section 5
         * "What does security by design mean for CII?" -> expects Security By Design Framework
         * "What are the supply chain security requirements?" -> expects CCoP 2.0 Section 8

       - For each query, run the retrieval pipeline (not full generation -- just retrieval + grading):
         * Use `create_rag_pipeline(settings)` or directly invoke the retrieval and grading nodes
         * Collect `filtered_documents` (post-grading results)
         * Check if expected_sections appear in the metadata of filtered documents
         * Calculate precision: (relevant retrieved) / (total retrieved) where "relevant" means document metadata matches expected_sections/expected_documents

       - Aggregate precision across all 10 queries
       - Assert: average precision >= 0.80 (80% threshold from Success Criterion 3)
       - Print per-query breakdown: query, precision, expected vs actual sections, pass/fail

       - Mark this test with `@pytest.mark.integration` since it requires live Databricks connection
       - Add a `@pytest.mark.skipif` to skip gracefully when Databricks credentials are not configured

    6. Run all tests: `cd src && poetry run pytest tests/ -v` (unit tests)
       Run precision benchmark: `cd src && poetry run pytest tests/retrieval/test_retrieval_precision.py -v -m integration` (requires Databricks)

    AVOID: Do NOT mock Databricks or Ollama for unit tests -- these tests cover pure logic (citation parsing, chunking). Integration testing with live services is the precision benchmark and human-verify checkpoint.
    AVOID: Do NOT hardcode CCoP section numbers in the ground truth -- use section descriptions that can tolerate minor parsing variations (e.g., "Section 5" matches "5", "5.", "Section 5").
