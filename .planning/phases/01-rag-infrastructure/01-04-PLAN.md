Implement citation extraction/formatting and integrate the RAG pipeline into the existing Clean Architecture with ports, adapters, DI wiring, and CLI command.

Purpose: This plan connects the RAG pipeline to the rest of the application. Citation resolution transforms raw citation anchors (created by Plan 01-03's generation node as `<c>citation_id</c>` tags) into human-readable end-of-response references (RAG-05). The Clean Architecture integration (RAG-06) ensures the RAG pipeline is accessible through the same patterns as the existing evaluation framework -- port interfaces, adapter implementations, DI container, CLI commands.

Output: Working CLI command `ccop-eval query "What are the access control requirements?"` that returns a formatted response with end-of-response citations referencing specific CCoP clauses.
</objective>

  <action>
    Plan 01-03 created `generation.py` with raw `<c>citation_id</c>` anchors in LLM output. This task adds the resolution and formatting layer on top.

    1. Create `src/retrieval/citations/__init__.py` (empty)

    2. Create `src/retrieval/citations/resolver.py`:
       - Function `extract_citation_ids(generation: str) -> list[str]`:
         * Extracts citation IDs from LLM generation using regex: `r'<c>(.*?)</c>'`
         * Returns list of unique citation_ids in order of appearance
         * Handles edge case: no citations found -> return empty list

       - Function `resolve_citations(citation_ids: list[str], documents: list) -> list[dict]`:
         * Takes citation_ids and LangChain Document objects (with metadata)
         * For each citation_id, finds matching document by `metadata["citation_id"]`
         * Returns list of dicts: `{"document": str, "section": str, "clause": str, "citation_id": str, "document_type": str}`
         * Deduplicates: if same citation_id appears multiple times, include only once
         * If citation_id not found in documents, log warning and skip (don't crash)

       - Function `build_citations_from_state(state: dict) -> list[dict]`:
         * Convenience function that:
           - Extracts citation_ids from `state["generation"]`
           - Resolves against `state["filtered_documents"]`
           - Returns resolved citations list

    3. Create `src/retrieval/citations/formatter.py`:
       - Function `format_response_with_citations(generation: str, citations: list[dict]) -> str`:
         * Removes citation anchors `<c>...</c>` from response text (clean text for user)
         * Appends end-of-response references:
           ```
           References:
           [1] CCoP 2.0, Section 5: Access Control, Clause 5.2.1
           [2] Auditing Guidelines, Section 3: Audit Methodology, Clause 3.1.2
           ```
         * Format per citation: `[{n}] {document}, {section}, Clause {clause}`
         * If section or clause is empty, omit that part gracefully
         * If no citations: return generation text as-is (no "References:" section)

       - Function `format_model_only_response(generation: str) -> str`:
         * Prepends a notice: "[Note: This response is based on model knowledge only, not grounded in specific CCoP document retrieval.]"
         * Returns formatted string
         * No references section

    4. Update `src/retrieval/nodes/generation.py` (ALREADY EXISTS from Plan 01-03):
       - Plan 01-03 created this file with raw LLM generation containing `<c>...</c>` anchors
       - ADD post-processing after LLM generation:
         * Call `build_citations_from_state(state)` to resolve raw anchors to citation metadata
         * Call `format_response_with_citations()` to produce final formatted output
       - Store both raw and formatted generation in state:
         * `state["raw_generation"]` = LLM output with anchors (preserve for debugging)
         * `state["generation"]` = formatted output with clean text + end-of-response references
         * `state["citations"]` = resolved citation list
       - The existing LLM invocation and context formatting from Plan 01-03 stays unchanged. Only add the post-processing step.

    AVOID: Do NOT embed citation metadata directly in chunk text (anti-pattern from research -- degrades retrieval quality). Use lightweight `<c>citation_id</c>` anchors only.
    WHY end-of-response references: CONTEXT.md explicitly locks this format -- "End-of-response references (clean response text, sources listed at bottom)".
  </action>

    - Test formatting: `format_response_with_citations("Access control requires...", [{"document": "CCoP 2.0", "section": "5", "clause": "5.2.1", ...}])` produces clean text with references
    - Test edge cases: empty citations, missing metadata fields, duplicate citation_ids
    - Test model-only formatting includes the notice
  </verify>

       - Define `RagResponse` (Pydantic BaseModel):
         * `response` (str): Formatted response with citations
         * `raw_response` (str): Raw LLM output
         * `is_rag_augmented` (bool): Whether RAG context was used
         * `citations` (list[dict]): Resolved citations
         * `retrieval_attempts` (int): Number of retrieval attempts
         * `grading_scores` (list[float]): Document relevance scores
         * `query` (str): Original query

    2. Create `src/application/use_cases/query_compliance.py`:
       - Class `QueryComplianceUseCase`:
         * Constructor: takes `rag_pipeline: IRagPipeline`, `logger: ILogger`
         * Method `async def execute(self, question: str) -> RagResponse`:
           - Validates question is not empty
           - Calls `self.rag_pipeline.query(question)`
           - Logs: query, is_rag_augmented, citation_count, retrieval_attempts
           - Returns RagResponse
       - This follows the same pattern as existing EvaluateModelUseCase

         * `async def query(self, question: str) -> RagResponse`:
           - Invokes the compiled graph pipeline
           - Maps graph state to RagResponse
           - Handles errors gracefully (return error response, don't crash)
         * `async def is_available(self) -> bool`:
           - Checks if Databricks settings are configured
