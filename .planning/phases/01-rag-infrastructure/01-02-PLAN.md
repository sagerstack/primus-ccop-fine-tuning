<objective>
Upload parsed CCoP chunks to Databricks Delta table and create a hybrid vector search index with BGE embeddings and built-in reranking.

Purpose: This plan creates the vector store that the retrieval pipeline queries against. Databricks Mosaic AI Vector Search with hybrid search (dense + sparse via RRF) achieves 85% NDCG@10 vs 72% for dense-only. Built-in reranking adds another +15% accuracy with a single parameter. This is the data layer that makes retrieval work.

Output: Databricks Delta table populated with all CCoP chunks, Delta Sync vector search index with hybrid search and reranking enabled, and an end-to-end ingestion script.
</objective>

  <action>
    1. Create `src/rag/ingestion/indexers/__init__.py` (empty)

    2. Create `src/rag/ingestion/indexers/databricks_indexer.py`:

       - Class `DatabricksIndexer` that:
         - Takes Databricks settings (host, token, catalog, schema, vector_search_endpoint, embedding_endpoint) via constructor from Settings
         - Method `create_source_table(chunks: list[CcopChunk]) -> str`:
           * Connects to Databricks using `databricks.sdk.WorkspaceClient`
           * Creates a Delta table at `{catalog}.{schema}.ccop_parsed_clauses` with columns:
             - `id` (STRING, primary key)
             - `text` (STRING, for embedding)
             - `document_source` (STRING)
             - `section` (STRING)
             - `subsection` (STRING)
             - `clause` (STRING)
             - `citation_id` (STRING)
             - `document_type` (STRING)
             - `page` (INT, nullable)
           * Uploads chunk data as rows using Databricks SQL or Spark DataFrame
           * Returns the full table name
           * Logs row count after upload

         - Method `create_vector_search_index(source_table: str) -> str`:
           * Uses `databricks.vector_search.client.VectorSearchClient`
           * Creates a Delta Sync index at `{catalog}.{schema}.ccop_clauses_hybrid`:
             - `primary_key="id"`
             - `index_type="DELTA_SYNC"`
             - `embedding_source_column="text"`
             - `embedding_model_endpoint_name` from settings (databricks-bge-large-en)
           * Enables hybrid search with sparse search on the `text` field
           * Returns the index name
           * Logs index creation status

         - Method `wait_for_index_ready(index_name: str, timeout_seconds: int = 600)`:
           * Polls index status until ONLINE or timeout
           * Logs progress every 30 seconds
           * Raises error on timeout

         - Method `verify_index(index_name: str, sample_query: str = "access control requirements") -> dict`:
           * Runs a sample similarity search query
           * Returns results with metadata
           * Logs result count and top result

         - Method `index_chunks(chunks: list[CcopChunk]) -> str`:
           * Orchestrates: create_source_table -> create_vector_search_index -> wait_for_index_ready -> verify_index
           * Returns index name
           * This is the main entry point

       IMPORTANT: Handle the Databricks setup complexity (Pitfall 4 from research):
       - Check Unity Catalog permissions before creating table
       - Verify embedding endpoint accessibility before creating index
       - Test with small sample (first 10 chunks) before full upload if debug mode
       - Provide clear error messages for common failures (permissions, endpoint not found, schema mismatch)

       AVOID: Do NOT hardcode catalog, schema, or endpoint names — all from Settings.
       AVOID: Do NOT use raw SQL strings for table creation without parameterization.
       WHY Delta Sync: Auto-syncs Delta table changes to vector index — if we re-run ingestion with updated chunks, the index updates automatically without manual re-indexing.
  </action>

    - DatabricksIndexer can be instantiated with settings (mock test, no actual Databricks connection)
    - Code handles missing Databricks credentials gracefully (clear error message)
  </verify>
