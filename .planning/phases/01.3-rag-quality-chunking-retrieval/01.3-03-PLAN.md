    1. **Ensure Qdrant is running:** Check that Docker Compose Qdrant service is up. If not, start it: `cd src && docker compose up -d qdrant`

    ```bash
    cd src && python -m rag.ingestion.run_ingestion --ccop-dir ../ccop-official
    ```
    This will:
    - Parse all 8 CCoP PDFs with Docling
    - Chunk with clause-aware splitter
    - Delete existing Qdrant collection and recreate
    - Generate dense + sparse embeddings
    - Upload all chunks to Qdrant
    - Verify with sample query

    3. **Capture and analyze output:**
    - Total chunk count (expect ~180+ across all 8 documents)
    - Per-document chunk counts
    - Chunk size distribution (min/max/avg/median token counts)
    - Sample query verification results

    4. **Verify chunk quality with Qdrant API:**
    ```bash
    # Get collection info
    curl -s http://localhost:6333/collections/ccop_clauses_hybrid | python -m json.tool

    # Sample a few points to verify metadata structure
    curl -s http://localhost:6333/collections/ccop_clauses_hybrid/points/scroll -X POST \
      -H "Content-Type: application/json" \
      -d '{"limit": 5, "with_payload": true, "with_vector": false}' | python -m json.tool
    ```
    Verify:
    - Point payloads have `clause`, `section`, `chapter`, `parent_path`, `citation_id` fields
    - `citation_id` follows `{source}::{clause}` format
    - No ToC or boilerplate chunks visible
    - Chunk text contains actual regulatory content at clause level

    If chunk count is significantly below 150, investigate: check which documents produced few chunks, whether Docling parsing failed for any document, whether regex pattern doesn't match document numbering format. Log findings.
