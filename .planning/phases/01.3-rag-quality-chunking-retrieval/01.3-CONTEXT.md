# Phase 1.3: RAG Quality — Clause-Level Chunking & Retrieval - Context

**Gathered:** 2026-03-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix retrieval precision by replacing flat PDF parsing with structure-aware Docling parser, implementing clause-boundary chunking for regulatory documents, removing broken RRF threshold, and adding cross-encoder reranking. Transforms 66 coarse chunks into ~180+ clause-level chunks where each chunk maps to one regulatory requirement.

Scope: Parser, chunker, chunk IDs, grading node refactor, reranking node, retrieval evaluation script. Does NOT include contextual chunking (prepending parent context), cross-reference graph, or weighted fusion — those are deferred experiments.

</domain>

<decisions>
## Implementation Decisions

### Chunk granularity
- Leaf-level chunking: each chunk = one lowest-level clause (e.g., 5.2.1.1)
- Parent clause intro text becomes its own chunk if it has standalone content
- Parent hierarchy path stored in metadata (clause_id, parent_path, chapter, section) — not prepended to chunk text
- Tables: entire table = one chunk with markdown formatting (not row-level)
- Tiny clauses (under ~30 tokens): merge with parent clause — avoids noise from cross-references and one-liners

### Document handling
- Same Docling parser for all 8 documents — no type-specific handling
- Boilerplate exclusion: use Docling's structural labels (ToC, page_header, page_footer) to filter — not page ranges
- Cross-references: stay as plain text in chunks, no metadata extraction (deferred)

### Retrieval pipeline
- Keep RRF (k=60) for hybrid fusion — rank-based, no score normalization needed, Qdrant native support
- Funnel shape configurable via settings: default retrieve 20 → rerank → top 3 to LLM
- Cross-encoder: ms-marco-MiniLM-L12-v2 (33M params, runs locally, ~200ms for 20 candidates)
- RRF threshold (0.6): removed entirely — top-N selection replaces threshold-based filtering
- Grading node becomes measurement-only: logs reranker scores for experiment tracking, no filtering

### Evaluation framework
- Use all 118 existing test cases (ground-truth/phase-2/test-suite/)
- 94% already have clause_reference annotations — use as ground truth for retrieval metrics
- Report metrics in two groups: retrieval-focused (71 cases: B2, B3, B5, B6, B12) and reasoning-focused (47 cases: B7-B20)
- RAGAs integration for context_precision and context_recall
- Reranker confidence scores logged as secondary metric
- Auto-generated experiment report per run: chunk stats, retrieval metrics per benchmark group, reranker score distribution, before/after comparison
- Results recorded in research/eval/experiment-log.md

### Claude's Discretion
- Exact minimum token threshold for tiny clause merging (approximately 30 tokens)
- Docling pipeline choice (classic vs VLM) based on performance testing
- Clause boundary regex patterns for non-standard numbering formats
- Report template format and layout

</decisions>

- Reranker scores (not RRF scores) are the comparable metric across experiments — RRF is the fusion mechanism, reranker measures quality
- The 118 test cases were curated to cover all CCoP sections with 39 unique clause references across Sections 2, 3, 5, 6, 7, 9, 10
- Experiment log already created at research/eval/experiment-log.md with Experiment 0 (baseline) documented
- Full research at artifacts/research/2026-03-02-rag-chunking-retrieval-strategies-technical.md

</specifics>

<deferred>
## Deferred Ideas

- **Contextual chunking (Anthropic approach)**: Prepend parent hierarchy to chunk text before embedding. Add as Experiment 4 after baseline clause-level results are measured.
- **Cross-reference metadata**: Parse inter-document references and store as metadata for multi-hop retrieval. Revisit if multi-hop queries show gaps in Phase 2 evaluation.
- **Weighted fusion (alpha blending)**: Replace RRF with configurable dense/sparse weighting. Research shows 5-10% improvement when alpha is tuned. Experiment after clause-level chunking + reranking are validated.
- **RAGAs faithfulness + answer_relevancy**: Generation-stage metrics. Defer to Phase 1.1 (Eval Infrastructure) where MLflow is set up.

</deferred>
