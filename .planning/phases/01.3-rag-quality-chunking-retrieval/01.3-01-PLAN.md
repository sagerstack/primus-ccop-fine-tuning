<objective>
Replace the broken ingestion pipeline (PyMuPDF4LLM + MarkdownHeaderTextSplitter) with Docling parser and clause-aware regex chunker. This is the core fix for retrieval precision — transforming 66 coarse section-level chunks into ~180+ clause-level chunks where each chunk maps to one regulatory requirement.

Purpose: The current pipeline produces only 66 chunks (87 before UUID collision) for 8 regulatory documents spanning 200+ pages. Clause-level granularity is non-negotiable for compliance Q&A — auditors need answers traced to specific clauses (e.g., "Clause 5.2.1"), not "somewhere in Section 5."

Output: New Docling parser, clause-aware chunker, updated ingestion models, updated orchestrator. Parser and chunker files are new; models.py and run_ingestion.py are modified.
</objective>

<task type="auto">
  <name>Task 2: Extend ingestion models and create clause-aware chunker</name>
  <files>
    src/rag/ingestion/models.py
    src/rag/ingestion/chunkers/clause_aware_chunker.py
  </files>
  <action>
    1. **Extend `src/rag/ingestion/models.py`** — add two fields to ChunkMetadata:
    - `parent_path: str = Field(default="", description="Hierarchy path (e.g., 'Chapter 5 > Section 5.2 > 5.2.1')")` — stores full clause hierarchy in metadata only (NOT prepended to chunk text, per CONTEXT.md decision)
    - `chapter: str = Field(default="", description="Top-level chapter number (e.g., '5')")` — enables chapter-level aggregation in evaluation

    Keep all existing fields unchanged. These are additive-only changes.

    2. **Create `src/rag/ingestion/chunkers/clause_aware_chunker.py`** with:

    **`CLAUSE_PATTERN`**: Compiled regex matching CCoP clause numbering: `r'^(\d+(?:\.\d+)*)\s+(.+?)$'` with `re.MULTILINE`. This matches patterns like "5.2.1 The CIIO shall..." at the start of a line.

    **`chunk_by_clauses(markdown_text: str, document_name: str) -> List[CcopChunk]`**:
    - Use `CLAUSE_PATTERN.split(markdown_text)` to split on clause boundaries
    - Iterate groups of 3 (clause_number, heading, content) from split result
    - Build chunk text: `f"{clause_number} {clause_heading}\n\n{clause_content}".strip()`
    - For tiny chunks (word count < 30): merge with previous chunk (append text), do not drop. Use a merge buffer pattern similar to existing section_chunker.py
    - For table detection: check if content contains markdown table markers (`|---` pattern). Keep entire table + surrounding clause text as one chunk (do not split mid-table)
    - Build ChunkMetadata:
      - `document_source`: document_name parameter
      - `section`: extract parent section from clause_number (e.g., "5.2" from "5.2.1")
      - `clause`: clause_number (e.g., "5.2.1")
      - `citation_id`: `f"{document_name}::{clause_number}"` — deterministic, human-readable
      - `chapter`: first number from clause (e.g., "5" from "5.2.1")
      - `parent_path`: build hierarchy string (e.g., "Chapter 5 > Section 5.2 > 5.2.1")
      - `page`: None (Docling markdown doesn't carry page numbers per-section)
    - Chunk ID: `f"{document_name}::{clause_number}"` — NOT UUID, deterministic
    - Handle pre-clause content (text before first numbered clause): if substantial (>50 words), create a chunk with clause="" and section="preamble"

    **`_filter_boilerplate(markdown_text: str) -> str`**:
    - Remove table of contents blocks: detect patterns like "Table of Contents", "CONTENTS", "TABLE OF CONTENTS" and remove until next heading
    - Remove page header/footer artifacts: lines matching common patterns like "Page X of Y", "CCoP 2.0 Second Edition", standalone page numbers
    - This is a best-effort filter — Docling's structural labels may handle most cases, but the regex fallback catches any remaining noise

    **`chunk_all_documents_by_clauses(parsed_docs: Dict[str, str]) -> List[CcopChunk]`**:
    - Iterate parsed_docs dict
    - For each document: call _filter_boilerplate first, then chunk_by_clauses
    - Mark "CCoP Response to Feedback" chunks as document_type="clarification" (same pattern as existing section_chunker.py)
    - Return combined list of all chunks
    - Log per-document chunk counts and total

    **Helper `_extract_section(clause_number: str) -> str`**:
    - Extract parent section: "5.2.1" -> "5.2", "5.2.1.1" -> "5.2.1", "5" -> "5"
    - Simple: rsplit(".", 1)[0] if "." in clause_number, else clause_number

    **Helper `_build_parent_path(clause_number: str) -> str`**:
    - Build hierarchy: "5.2.1" -> "Chapter 5 > Section 5.2 > 5.2.1"
    - Split on "." and build progressive path

    Do NOT delete or modify `section_chunker.py`. It remains as the legacy chunker.
  </action>
