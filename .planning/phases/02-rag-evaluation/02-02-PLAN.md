<objective>
Wire the LangGraph RAG pipeline into the evaluation use case, replacing direct model_gateway calls.

Purpose: Core integration -- evaluation now routes through the same LangGraph graph that `query ask` uses. This means test cases get RAG-augmented responses (hybrid mode) or clean LLM-only responses (llm-only mode) from the graph. The graph output becomes the evaluation input for benchmark scoring and RAGAs metrics. `filtered_documents` from the graph flow to RAGAs as `retrieved_contexts`.

Output: EvaluateModelUseCase calls IRagPipeline instead of IModelGateway. Container wires the dependency.
</objective>

  <files>

  <action>
    This is the core integration task. The use case currently calls `model_gateway.generate_response()` directly. Replace this with calls to `rag_pipeline.query()`.

    1. Add `rag_pipeline` parameter to `__init__`:
       - Type: Optional (import from `rag.application.ports.i_rag_pipeline` using TYPE_CHECKING to avoid circular imports)
       - Default: None (backward compatibility -- if no RAG pipeline, fall back to model_gateway)
       - Store as `self._rag_pipeline`

    2. Modify `_evaluate_test_case` method to route through the RAG graph:

       **When rag_pipeline is available AND evaluation_mode is set:**

       a. Get mode from request: `mode = request.evaluation_mode` (defaults to "hybrid")

       b. Check RAG pipeline availability for the requested mode:
          ```python
          if self._rag_pipeline is not None:
              is_rag_available = await self._rag_pipeline.is_available(mode)
              if mode == "hybrid" and not is_rag_available:
                  raise ValueError(
                      f"RAG pipeline not available for hybrid mode. "
                      f"Ensure Qdrant is running and configured. "
                      f"Use --mode llm-only to evaluate without RAG."
                  )
          ```

       c. Call RAG pipeline instead of model_gateway:
          ```python
          rag_response = await self._rag_pipeline.query(
              question=test_case.question,
              mode=mode,
          )
          ```

       d. Build a ModelResponse from the RagResponse output:
          ```python
          model_response = ModelResponse(
              content=rag_response.response,
              model_name=request.model_name,
              tokens_used=0,  # Not tracked from graph this phase
              latency_ms=0,   # Not tracked from graph this phase
              temperature=request.temperature,
          )
          ```
          Note: tokens_used and latency_ms are 0 because the graph doesn't expose these yet (deferred per CONTEXT.md). The important thing is the response content for scoring.

       e. Extract retrieved_chunk_ids from RagResponse citations:
          ```python
          retrieved_chunk_ids = []
          if rag_response.citations:
              for citation in rag_response.citations:
                  chunk_id = f"{citation.get('document', 'Unknown')}::{citation.get('clause', citation.get('section', 'N/A'))}"
                  retrieved_chunk_ids.append(chunk_id)
          chunk_count = len(retrieved_chunk_ids) if retrieved_chunk_ids else 0
          ```

       f. Extract retrieved context strings for RAGAs:
          - RagResponse doesn't expose raw document content directly, but the graph's `filtered_documents` are not accessible from RagResponse.
          - Solution: Enhance LangGraphRagAdapter to expose filtered_documents. But that changes another file not in this plan...
          - Alternative: Use `rag_response.response` as the context when `rag_response.is_rag_augmented` is True. BUT this is the generated response, not the retrieved context.
          - Best approach for this plan: The LangGraphRagAdapter already has access to `final_state["filtered_documents"]`. Add a `retrieved_contexts` field to RagResponse to carry the document text. This is a small addition to the port.

          Add to `i_rag_pipeline.py` RagResponse:
          ```python
          retrieved_contexts: list[str] = Field(
              default_factory=list, description="Text content of retrieved documents for RAGAs evaluation"
          )
          ```

          Update `langgraph_rag_adapter.py` to populate it:
          ```python
          retrieved_contexts=[
              doc.page_content for doc in final_state.get("filtered_documents", [])
          ],
          ```

       g. Pass retrieved_contexts to RAGAs (replacing the hardcoded None):
          ```python
          retrieved_contexts = rag_response.retrieved_contexts if rag_response.is_rag_augmented else None
          ragas_evaluation = self._ragas_service.evaluate_response(
              question=test_case.question,
              response=model_response.content,
              reference=reference,
              retrieved_contexts=retrieved_contexts,
              key_facts=key_facts if isinstance(key_facts, list) and len(key_facts) > 0 else None,
          )
          ```

       **When rag_pipeline is None (backward compatibility):**
       - Fall back to existing model_gateway.generate_response() path
       - retrieved_chunk_ids = None, chunk_count = None, evaluation_mode = None

    3. Pass RAG metadata to EvaluationResult constructor:
       ```python
       result = EvaluationResult(
           test_case=test_case,
           model_response=model_response,
           metrics=metrics,
           ragas_evaluation=ragas_evaluation,
           retrieved_chunk_ids=retrieved_chunk_ids,
           chunk_count=chunk_count,
           evaluation_mode=request.evaluation_mode if self._rag_pipeline else None,
       )
       ```

    4. Update `_result_to_dto` to pass new fields:
       ```python
       return EvaluationResultDTO(
           ...existing fields...,
           evaluation_mode=result.evaluation_mode,
           retrieved_chunk_ids=result.retrieved_chunk_ids,
           chunk_count=result.chunk_count,
       )
       ```

    5. Update `_build_evaluation_metadata` to include evaluation_mode:
       ```python
       metadata["evaluation_mode"] = request.evaluation_mode
       ```

    6. Keep model_gateway for `is_model_available` check. The graph doesn't have a model availability check, but the existing check verifies the model exists. For hybrid mode, also check rag_pipeline availability.

    IMPORTANT files also touched by this task (small changes):

    - `src/rag/infrastructure/adapters/langgraph_rag_adapter.py`: Populate `retrieved_contexts` from filtered_documents
