## Glob + legacy-skip behavior

- Discovery pattern: `self._results_dir.rglob(f"*-{model_name}.json")`. This matches both the monthly subdir pattern (`{yyyy-MM}/{run_id}-{model}.json`) and any other path that happens to share the `*-{model}.json` suffix.
- Files named `*-contexts.json` are sidecars and are filtered by name check *before* any JSON parse attempt.
- Files without `metadata.run_id` or `schema_version != 6` are logged at WARNING level with message `Skipping legacy pre-v6 result file: {path}` and dropped from the result list.
- Broken/unparseable JSON is logged at WARNING and skipped (no exception surfaces to callers).
- `GenerateReportUseCase.get_summary` inspects the flat directory for legacy `{model}_results.json` sentinels when zero v6 results are found, emitting a guidance message pointing the user to re-run evaluations for schema-v6 output.

## CLI --verbose-io behavior

- Flag added: `--verbose-io` on `ccop-eval evaluate run`. Boolean default False.
- Sidecar read is *lazy*: file is opened only when `verbose_io=True` *and* the computed `{results_dir}/{yyyy-MM}/{run_id}-contexts.json` exists. Missing file is a silent no-op.
- Sidecar is keyed by `test_id`. Entries are dicts expected to contain `citation_id`, `section`, `clause`, `score`, `text`. Missing keys degrade to `"?"` / empty string / empty display — no crash.
- The same panel already prints `Retrieved Citations` (chunk IDs) in hybrid mode; the new `Retrieved Contexts (detailed)` block is additional and only renders under `--verbose-io`.
- Token display is always on for v6 results (non-zero total triggers the `prompt=X completion=Y total=Z` form in the Response header); the `--verbose-io` flag additionally prints a dedicated `Tokens:` line before the citation block.

## Gotchas encountered

1. **`TestCase` invariant trap during reconstruction**: `TestCase.__post_init__` asserts `len(question.strip()) >= 50` and non-empty `expected_response`. Early reconstructions of persisted test_results used the short persisted question as-is, which raised for any real benchmark question containing <50 chars of user text. Fix: pad with trailing spaces and hard-code a non-empty `expected_response` placeholder. This is only for *reporting* reconstruction — the persisted JSON itself is not touched, and the padding has no effect on summary math.
2. **Sidecar filter order**: the `-contexts.json` suffix check must happen *before* the JSON parse so that a malformed sidecar doesn't trigger a spurious WARNING. Filtering by name first keeps the log signal clean.
3. **`load_by_model` sort**: `sorted(rglob(...))` ensures deterministic order across filesystems; without it, report output could fluctuate between runs on macOS vs Linux.
4. **Live smokes deferred**: per user instruction, the plan's interactive smokes (`ccop-eval evaluate run --model primus-reasoning --test-ids B3-001 --mode llm-only --verbose-io` and the `report summary` smoke) were not executed in this session. Static inspection verifies from the plan pass; full behavioral verification requires a live Ollama run.
