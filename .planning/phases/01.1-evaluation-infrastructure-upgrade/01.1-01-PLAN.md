**Part B: Redesign JudgeEvaluation dataclass**

In `src/domain/services/llm_judge_service.py`, replace the fixed JudgeEvaluation:

Current (remove):
```python
@dataclass
class JudgeEvaluation:
    accuracy_score: int  # 1-5
    completeness_score: int  # 1-5
    alignment_score: int  # 1-5
    justification: str
    overall_score: float  # 0-1
    confidence: float  # 0-1
    raw_response: str
```

New (replace with):
```python
@dataclass
class DimensionScore:
    """Single dimension score from LLM judge."""
    dimension: str      # e.g., "gap_prioritization"
    score: int          # 0-3 anchored
    weight: float       # from rubric (e.g., 1.0)

@dataclass
class JudgeEvaluation:
    """LLM judge evaluation result with dynamic dimensions."""
    dimensions: list[DimensionScore]
    justification: str
    overall_score: float    # 0-1 normalized: weighted_sum / (3.0 * total_weight)
    confidence: float       # 0-1
    raw_response: str
    benchmark_type: str     # e.g., "B8"
    error: str | None = None  # Non-None means judge failed
```

**Part D: Add judge_metric factory to evaluation_metric.py**

Add a factory function for LLM-as-Judge metrics:
```python
def judge_metric(dimension_name: str, raw_score: int, weight: float = 1.0) -> EvaluationMetric:
    """Create metric from LLM judge 0-3 score, normalized to 0-1."""
    normalized = raw_score / 3.0
    return EvaluationMetric(
        name=dimension_name,
        value=normalized,
        weight=weight,
        description=f"LLM judge: {dimension_name} ({raw_score}/3)"
    )
```

**What to avoid and WHY:**
- Do NOT hardcode rubric text in Python strings — load from evaluation-rubrics.md. Rubrics evolve; code should reference, not embed (Pitfall 6 from research).
- Do NOT use 1-5 scale — use 0-3 anchored per criteria-establishment.md. 1-5 has consistency issues (Pitfall 2).
- Do NOT use generic rubric prompts — each benchmark must have its own dimensions and anchors. Generic causes score inflation.
- Do NOT fall back to conservative scores on judge error — flag as error so the evaluation pipeline can handle it (skip and flag pattern from context decisions).
