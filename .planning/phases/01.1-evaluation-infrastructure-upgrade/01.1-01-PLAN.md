<task type="auto">
  <name>Task 2: Redesign JudgeEvaluation and upgrade LLMJudgeService</name>
  <files>src/domain/services/llm_judge_service.py</files>
  <action>
Redesign the LLMJudgeService in place. Changes:

1. **Replace JudgeEvaluation dataclass** with dynamic dimensions:
   ```python
   @dataclass
   class JudgeDimension:
       name: str        # e.g., "gap_prioritization"
       score: int       # 0-3
       weight: float    # e.g., 1.0
       justification: str  # per-dimension reasoning

   @dataclass
   class JudgeEvaluation:
       dimensions: List[JudgeDimension]
       overall_score: float    # 0-1 normalized (weighted average of dimensions / 3.0)
       confidence: float       # 0-1
       raw_response: str
       judge_error: bool = False  # True when judge call failed
       error_message: str = ""    # Error details when judge_error=True
   ```

2. **Add rubric loading** — load benchmark-specific rubric from `docs/phase-2/evaluation-rubrics.md` at runtime. Parse the markdown to extract dimension definitions, anchors, and prompt template for a given benchmark. Use a simple parsing approach: find the section header for the benchmark (e.g., "### B8: Gap Prioritization"), extract content until next "###" header. Cache parsed rubrics in a class-level dict.

3. **Redesign _build_judge_prompt** to accept benchmark_type (str like "B8") instead of a rubric dict. Load the rubric template from evaluation-rubrics.md and fill in {question}, {response}, {expected_response}, {key_facts} placeholders.

4. **Change evaluate_response signature** to:
   ```python
   def evaluate_response(self, test_case: TestCase, response: ModelResponse, benchmark_type: str) -> JudgeEvaluation
   ```
   The benchmark_type string (e.g., "B8") selects which rubric to load.

5. **Fix error handling** — on judge call failure or parse error, return JudgeEvaluation with `judge_error=True`, `error_message=str(e)`, empty dimensions list, `overall_score=None` (or 0.0), `confidence=0.0`. Do NOT return fallback scores (no more defaulting to 3/3/3 with 0.6 overall). Missing data is better than wrong data.

6. **Update _parse_judge_response** to handle the new JSON schema:
   ```json
   {
     "dimensions": [
       {"dimension": "gap_prioritization", "score": 2, "weight": 1.0, "justification": "..."}
     ],
     "confidence": 0.85
   }
   ```
   Calculate overall_score as weighted average: sum(score * weight) / (3.0 * sum(weight))

7. **Keep Claude subprocess call** (_call_claude_agent) unchanged — same subprocess pattern, same model.

Do NOT modify scoring_service.py in this task — that's Plan 04.
