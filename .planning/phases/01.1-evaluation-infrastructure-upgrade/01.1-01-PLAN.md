  <action>
    Redesign the `JudgeEvaluation` dataclass in `src/domain/services/llm_judge_service.py` to support dynamic benchmark-specific dimensions instead of the fixed accuracy/completeness/alignment fields.

    **Replace the existing JudgeEvaluation:**

    Current (to be replaced):
    ```python
    @dataclass
    class JudgeEvaluation:
        accuracy_score: int  # 1-5
        completeness_score: int  # 1-5
        alignment_score: int  # 1-5
        justification: str
        overall_score: float  # 0-1
        confidence: float  # 0-1
        raw_response: str
    ```

    New design:
    ```python
    @dataclass
    class DimensionScore:
        """Single dimension score from LLM judge."""
        name: str           # e.g., "gap_prioritization"
        score: int          # 0-3 anchored scale
        weight: float       # From criteria-establishment.md

    @dataclass
    class JudgeEvaluation:
        """LLM judge evaluation result with dynamic dimensions."""
        dimensions: List[DimensionScore]  # Benchmark-specific dimension scores
        justification: str                # CoT explanation with evidence
        overall_score: float              # 0-1 normalized (weighted avg of dimensions)
        confidence: float                 # 0-1 judge self-assessed confidence
        raw_response: str                 # Full judge response for debugging
        judge_error: bool = False         # True if evaluation failed (skip-and-flag)
        error_message: str = ""           # Error details when judge_error=True
    ```

    **Add helper methods to JudgeEvaluation:**

    - `@staticmethod from_dimensions(dimensions, justification, confidence, raw_response) -> JudgeEvaluation`:
      Calculates overall_score as weighted average: `sum(d.score * d.weight for d in dimensions) / (3.0 * sum(d.weight for d in dimensions))`. This normalizes the 0-3 scale to 0-1.

    - `@staticmethod error(error_message, raw_response="") -> JudgeEvaluation`:
      Creates a JudgeEvaluation with `judge_error=True`, empty dimensions, overall_score=0.0, confidence=0.0. This is the skip-and-flag pattern — no fallback scores, just an error marker.

    **Update imports:** Add `List` from typing if not already imported.

    **Do NOT change the LLMJudgeService class methods yet** — those will be upgraded in Plan 02. Only change the JudgeEvaluation dataclass and add DimensionScore. The existing evaluate_response, _build_judge_prompt, _parse_judge_response, and _call_claude_agent methods remain unchanged for now (they will temporarily not work correctly with the new dataclass, which is acceptable since Plan 02 follows immediately).

    **Rationale for changes:**
    - Dynamic dimensions: B8 has 1 dimension (gap_prioritization), but future multi-dimension benchmarks could have 2-3. List of DimensionScore handles both.
    - 0-3 integer scale: Matches criteria-establishment.md. Normalized to 0-1 only for aggregation.
    - judge_error flag: Skip-and-flag pattern per CONTEXT.md. No fallback conservative scores (the current try/except that returns 3/3/3 is wrong).
    - DimensionScore as separate dataclass: Clean separation, each dimension is self-documenting.
