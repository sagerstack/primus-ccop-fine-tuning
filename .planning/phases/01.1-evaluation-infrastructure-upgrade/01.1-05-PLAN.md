     a. Call `self._tracker.start_run(run_name=f"{request.model_name}_{request.mode}_{timestamp}", params={...})` with params: model, mode, test_case_count, benchmark_version, temperature, evaluation_phase

     c. If save_results is True, log the results JSON file as artifact: `self._tracker.log_artifact(filepath)`
     d. Call `self._tracker.end_run()` in a finally block (ensure cleanup)

4. **Add tracker to DI container**:
   - Add a factory method that creates MLflowTracker or NullTracker:
   ```python
   @staticmethod
   def _create_experiment_tracker(settings, enable_tracking=False):
       if enable_tracking:
           from infrastructure.adapters.tracking.mlflow_tracker import MLflowTracker
           return MLflowTracker(
               tracking_uri=settings.mlflow_tracking_uri,
               experiment_name=settings.mlflow_experiment_name,
           )
       else:
           from infrastructure.adapters.tracking.mlflow_tracker import NullTracker
           return NullTracker()
   ```
   - The tracker selection happens at CLI level (--track flag determines which to create), so the container should provide a factory that accepts the enable_tracking flag. Alternatively, make evaluate_model_use_case a Factory that accepts an experiment_tracker parameter directly.
   - The simplest approach: keep evaluate_model_use_case as a Factory, and pass the tracker from CLI code when creating the use case instance. The container provides the tracker factory, CLI picks MLflowTracker or NullTracker based on --track flag.
