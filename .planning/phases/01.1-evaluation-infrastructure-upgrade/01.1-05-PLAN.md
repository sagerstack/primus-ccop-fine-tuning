2. Update the `execute` method to wrap evaluation in tracking lifecycle:

```python
async def execute(self, request: EvaluationRequestDTO) -> EvaluationSummaryDTO:
    start_time = datetime.utcnow()
    # ... existing loading and validation ...

    # Start tracking if enabled
    tracking_active = (
        request.enable_tracking
        and self._experiment_tracker is not None
        and self._experiment_tracker.is_available()
    )

    if tracking_active:
        timestamp = start_time.strftime("%Y%m%d_%H%M%S")
        run_name = f"{request.model_name}_{request.mode}_{timestamp}"
        self._experiment_tracker.start_run(
            run_name=run_name,
            params={
                "model": request.model_name,
                "mode": request.mode,
                "test_case_count": len(test_cases),
                "benchmark_types": ",".join(request.benchmark_types),
                "temperature": request.temperature,
                "evaluation_phase": request.evaluation_phase,
                "pass_threshold": str(request.pass_threshold or "phase_default"),
            },
        )

    try:
        # ... existing evaluation loop (unchanged) ...

        # Generate summary
        summary = self._generate_summary(request.model_name, results, start_time, end_time)

        # Log tracking metrics
        if tracking_active:
            # Overall metrics
            self._experiment_tracker.log_metric("overall_accuracy", summary.overall_score)
            self._experiment_tracker.log_metric("passed_tests", float(summary.passed_tests))
            self._experiment_tracker.log_metric("failed_tests", float(summary.failed_tests))
            self._experiment_tracker.log_metric("total_tests", float(summary.total_tests))

            # Per-benchmark scores
            for benchmark, stats in summary.by_benchmark.items():
                # Clean benchmark name for metric key (replace non-alphanumeric)
                clean_name = benchmark.split("_")[0]  # "B8" from "B8_Gap_Prioritisation"
                self._experiment_tracker.log_metric(f"benchmark_{clean_name}", stats["score"])

            # Log results artifact
            if request.save_results:
                # The result repository already saved results — log the same file as artifact
                # Build artifact from summary
                import json
                import tempfile
                artifact_data = {
                    "model_name": summary.model_name,
                    "overall_score": summary.overall_score,
                    "total_tests": summary.total_tests,
                    "passed_tests": summary.passed_tests,
                    "by_benchmark": summary.by_benchmark,
                    "mode": request.mode,
                }
                with tempfile.NamedTemporaryFile(
                    mode='w', suffix='.json', prefix='eval_', delete=False
                ) as f:
                    json.dump(artifact_data, f, indent=2, default=str)
                    artifact_path = f.name
                self._experiment_tracker.log_artifact(artifact_path)

        # ... existing save results logic ...

        return summary

    finally:
        # Always end tracking run (even on error)
        if tracking_active:
            self._experiment_tracker.end_run()
```

Key integration points:
- Tracking wraps the entire evaluation in start_run/end_run
- Params logged at start: model, mode, count, benchmarks, temperature, phase, threshold
- Metrics logged after evaluation: overall_accuracy, per-benchmark scores, pass/fail counts
- Artifact: evaluation results JSON
- `finally` block ensures end_run is called even on errors

**What to avoid and WHY:**
- Do NOT log metrics during the evaluation loop (one per test case) — batch at end. Per-case logging creates too many MLflow API calls and confuses the metric timeline.
- Do NOT make experiment_tracker required — keep as Optional. Evaluation must work without MLflow.
- Do NOT log judge_error metrics to MLflow — they have weight=0 and would distort the dashboard.
- Do NOT use mlflow context manager here — we need explicit start_run/end_run because the tracking lifecycle spans async operations.
