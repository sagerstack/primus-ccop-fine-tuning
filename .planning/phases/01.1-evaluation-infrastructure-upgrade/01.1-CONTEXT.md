# Phase 1.1: Evaluation Infrastructure Upgrade - Context

**Gathered:** 2026-02-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Upgrade the evaluation scoring pipeline from semantic-similarity proxies to LLM-as-Judge rubrics for 15 benchmarks, unify all model queries through a single ModelGateway wrapping the LangGraph pipeline, and add MLflow experiment tracking to Databricks. The 6 rule-based benchmarks (B1, B2, B4, B5, B6, B21) remain unchanged. RAG pipeline internals are not refactored.

</domain>

<decisions>
## Implementation Decisions

### Eval Framework Architecture
- Scoring happens in the **application layer**, not inside LangGraph
- Flow: `EvaluateModelsUseCase` calls `IModelGateway.generate()` → gets response → calls `ScoringService.score()` → creates `EvaluationResult`
- LangGraph graph has **no scoring node** — it only handles routing, retrieval, and generation
- `IModelGateway` stays pure — only generates responses, no scoring concern
- ScoringService lives in the domain layer, calls LLMJudgeService for LLM-as-Judge benchmarks

### CLI Invocation Modes
- Three modes for the `evaluate` command:
  1. `--eval --file <file> --batch` — evaluate ALL questions in the file
  2. `--eval --file <file> --q <question-no>` — evaluate a SPECIFIC question from the file
  3. `--query "free text question"` — ad-hoc query, no evaluation (even if `--eval` is passed)
- The file is always the source of ground truth (expected responses, benchmark types, key facts)
- `--mode` flag controls LangGraph path: `hybrid`, `llm-only`, `rag-only`

### LLM Judge Design
- Judge LLM: **Claude Sonnet via Claude Agent SDK** (subprocess `claude chat`) — same as current implementation
- Scoring scale: **0–3 anchored** (aligned with criteria-establishment.md): 0=Incorrect, 1=Partial, 2=Complete, 3=Exceeds. Normalized to 0–1 for aggregation
- Judge error handling: **Skip and flag** — on failure, mark test case as `judge_error` with no score. No fallback scores. Missing data > wrong data
- Evaluation dimensions: **Benchmark-specific** — each of the 15 LLM-judged benchmarks gets its own dimensions from criteria-establishment.md (not a shared generic set)
- JudgeEvaluation data model: **Dynamic dimensions** — list of (dimension_name, score, weight) tuples instead of fixed fields

### Scoring Migration Strategy
- **Replace entirely** — remove `_score_reasoning_track` (semantic similarity) for B8, B9, B11, B15, B17, B18, B19. Remove `_score_b3_hallucination` misuse for B3. Implement new LLM judge scorers for B7, B10, B14, B16. Upgrade B12, B13, B20 rubrics
- SemanticSimilarityService can be removed after migration (no longer used by any scorer)
- Old results: **Keep 49.2% as historical** AND re-run 118 cases through new scoring to get a restated baseline under new methodology. Compare future runs against restated baseline

### ModelGateway Routing
- `ModelGateway` sits **outside** LangGraph as an infrastructure adapter implementing `IModelGateway`
- Replaces `OllamaGateway` — single gateway for all model queries
- Mode-based routing fully internal to LangGraph graph (`route_by_mode()` conditional edge)
- RAG unavailability: **Fail explicitly** — if mode=hybrid and Databricks unavailable, raise error. No silent fallback to llm-only
- `IModelGateway.generate(question, mode) -> ModelResponse` — caller sets mode, gateway handles routing

### MLflow Integration
- Storage: **Databricks MLflow** (centralized tracking, already have Databricks access)
- Organization: **One experiment, many runs** — single "CCoP Evaluation" experiment, each run is a different evaluation (baseline, RAG, fine-tuned, etc.)
- Run data: **Params + metrics + artifacts** — Parameters (model, mode, RAG config, benchmark set), Metrics (overall score, per-benchmark scores, hallucination rate), Artifacts (full results JSON, test case file)
- Trigger: **CLI flag** — `--track` flag enables MLflow logging. Without it, evaluation runs without tracking

### Claude's Discretion
- Rubric prompt structure for each of the 15 LLM-judged benchmarks (based on criteria-establishment.md anchors)
- Internal graph state design for passing mode and eval parameters
- MLflow run naming convention
- Error handling and logging detail level

</decisions>

<specifics>
## Specific Ideas

- Evaluation rubrics should be derived from `docs/phase-2/criteria-establishment.md` anchored 0–3 scale — each benchmark has specific anchors with CCoP-specific examples at each level
- The Component 4 document (`docs/phase-2/evaluation-rubrics.md`) should be created during this phase to formalize all 15 rubric prompts before implementation
- Benchmark categorization: 6 rule-based (B1, B2, B4, B5, B6, B21) + 15 LLM-as-Judge (B3, B7-B20) — all 21 benchmarks scoreable in a single automated run with no human/expert dependencies

</specifics>

## Deferred Ideas
