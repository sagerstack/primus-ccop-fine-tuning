# Phase 2.2: RAGAs Hallucination Metric and Metric Renaming - Research

**Researched:** 2026-03-20
**Domain:** RAGAs evaluation metrics, Python Rich library, metric aggregation
**Confidence:** HIGH

## Summary

Phase 2.2 requires adding a new hallucination metric using RAGAs faithfulness with ground-truth expected_response as context, renaming the existing faithfulness metric to context_faithfulness, restructuring CLI tables, fixing the overall score normalization bug, and adding scoring to the query command.

The research confirms:
1. RAGAs faithfulness metric can be called with arbitrary context via the `retrieved_contexts` parameter
2. Rich library does not support multi-level headers natively - workarounds required
3. Current overall score calculation has a normalization bug (sums weighted contributions without dividing by total weight when running subset of benchmarks)
4. Graph state contains all necessary data for expanded per-test-case panels (citations, prompt, system prompt)
5. Quality group structure already supports adding and renaming metrics

**Primary recommendation:** Use RAGAs faithfulness with `[expected_response]` as retrieved_contexts for hallucination metric. Rename faithfulness → context_faithfulness. Restructure tables without multi-level headers (use visual grouping instead). Fix normalization by dividing by sum of weights for present categories.

### Pattern 1: RAGAs Faithfulness with Custom Context

**What:** RAGAs faithfulness metric accepts any list of strings as `retrieved_contexts` parameter. To create a hallucination metric, pass `[expected_response]` instead of retrieved documents.

**When to use:** When you want to check if the model's response contains claims that go beyond or contradict the ground-truth answer.

**Example:**
```python
# Source: https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/faithfulness/
from ragas import SingleTurnSample, evaluate
from ragas.metrics import _Faithfulness

# Create sample with expected_response as context
sample = SingleTurnSample(
    user_input=test_case.question,
    response=model_response.content,
    reference=test_case.expected_response,
    retrieved_contexts=[test_case.expected_response],  # Ground truth as context
)

# Evaluate faithfulness against ground truth
scorer = _Faithfulness()
result = await scorer.single_turn_ascore(sample)
# Score represents: claims in response supported by expected_response / total claims
```

**How it works internally:**
1. Breaks response into individual claims
2. Checks each claim against context (in this case, expected_response)
3. Returns: number of supported claims / total claims
4. Score of 0.8 means 80% of claims are grounded in expected_response

**Key insight:** This is semantically different from context_faithfulness:
- **context_faithfulness:** Checks response against retrieved RAG documents (are you using the context correctly?)
- **hallucination:** Checks response against ground truth (are you making claims beyond the correct answer?)

### Pattern 3: Overall Score Normalization Fix

**What:** Current overall score calculation sums weighted contributions without dividing by total weight of present categories, producing incorrect scores when running subset of benchmarks.

**Current bug:**
```python
# evaluate_model.py line 364-367
weighted_score = sum(
    cat["average"] * cat["weight"]
    for cat in category_scores.values()
)
# BUG: Returns weighted_score directly without normalizing
return weighted_score
```

**Expected behavior:**
```python
# Calculate total weight of present categories
total_weight = sum(cat["weight"] for cat in category_scores.values())

# Normalize weighted sum by total weight
weighted_score = sum(
    cat["average"] * cat["weight"]
    for cat in category_scores.values()
)

# Normalize to 0-1 range
normalized_score = weighted_score / total_weight if total_weight > 0 else 0.0
return normalized_score
```

**Why normalization matters:**
- When all 5 categories present: weights sum to 1.0 (25% + 35% + 20% + 10% + 10%)
- When subset (e.g., only B1-B5): weights sum to 0.25 (25% only)
- Without normalization: overall score = 0.25 * avg_score (incorrect, appears 4x lower)
- With normalization: overall score = (0.25 * avg_score) / 0.25 = avg_score (correct)

### Anti-Patterns to Avoid

- **Modifying RAGAs internals:** Don't fork or patch RAGAs library. Use it as black box with documented API.
- **Breaking existing faithfulness:** Don't modify context_faithfulness behavior during rename. Only change the name.
- **Multi-level headers workaround via nested tables:** Don't nest Rich tables for headers. Causes alignment issues and poor readability.
- **Hardcoded metric names in aggregation:** Use QualityGroup.get_all_groups() and iterate, don't hardcode metric lists.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Hallucination detection | Custom claim extraction and verification | RAGAs faithfulness with custom context | Already tested, handles edge cases, integrated with existing pipeline |
| Table formatting with groups | Custom ASCII table rendering | Rich Table with visual separators | Rich handles colors, alignment, borders, and terminal width |
| Metric normalization | Custom weighted average logic | Existing category_weighted_score pattern with division fix | One-line fix vs reimplementation |

**Key insight:** RAGAs faithfulness is a general-purpose metric that works with any context. Using expected_response as context is a valid use case, not a hack.

## Common Pitfalls

### Pitfall 1: Forgetting to Divide by Total Weight

**What goes wrong:** Overall score appears much lower than expected when running subset of benchmarks (e.g., 0.18 instead of 0.75).

**Why it happens:** Code sums weighted contributions (e.g., 0.25 * 0.75 = 0.1875) but returns that directly instead of dividing by sum of weights (0.1875 / 0.25 = 0.75).

**How to avoid:** Always normalize weighted sum by total weight when categories can vary.

**Warning signs:** Overall score drops proportionally to number of categories missing (1 category = score/4, 2 categories = score/2, etc.).

**Code location:** `evaluate_model.py` line 364-371 in `_calculate_category_weighted_score()`.

### Pitfall 2: Breaking Backward Compatibility in JSON

**What goes wrong:** Existing evaluation results fail to load after renaming faithfulness to context_faithfulness.

**Why it happens:** JSON deserialization expects old field names.

**How to avoid:**
1. Increment schema_version to 3
2. Add migration logic in repository to handle old field names
3. OR use alias in Pydantic model to accept both names

**Warning signs:** KeyError or validation errors when loading old results.

**Code location:** `json_result_repository.py` and `evaluation_result_dto.py`.

### Pitfall 3: Inconsistent Metric Names Across Layers

**What goes wrong:** Metric shows as "faithfulness" in JSON but "context_faithfulness" in CLI, or vice versa.

**Why it happens:** Renaming propagates to only some layers (domain, DTO, CLI, JSON).

**How to avoid:**
1. Use QualityGroup.get_display_name() consistently for CLI display
2. Use internal names (context_faithfulness, hallucination) in DTOs and JSON
3. Grep codebase for old name before committing

**Warning signs:** Mismatches between CLI display and JSON output.

**Checklist:**
- [ ] quality_group.py metrics list updated
- [ ] quality_group.py display names updated
- [ ] ragas_evaluation_service.py metric names updated
- [ ] evaluate.py CLI display updated
- [ ] query.py CLI display updated (if showing scores)
- [ ] json_result_repository.py group key mapping updated
- [ ] Tests updated

### Pitfall 4: Adding Hallucination to Wrong Quality Group

**What goes wrong:** Hallucination metric shown in "Model-RAG Grounding" group instead of "Model Response Quality".

**Why it happens:** Confusion about what hallucination measures (checks against ground truth, not retrieved context).

**How to avoid:**
- context_faithfulness = checks response vs retrieved RAG documents → Model-RAG Grounding
- hallucination = checks response vs ground truth expected_response → Model Response Quality

**Warning signs:** Hallucination metric shows N/A in llm-only mode (it should work in both modes).

**Semantic distinction:**
- **Grounding metrics:** Are you using the context you retrieved? (RAG-dependent)
- **Response quality metrics:** Are you making up claims beyond the correct answer? (RAG-independent)

### Pitfall 5: Query Command Scoring Without Retrieved Contexts

**What goes wrong:** RAGAs scoring fails in query command because retrieved_contexts field is empty.

**Why it happens:** RagResponse.retrieved_contexts only populated in hybrid mode, not llm-only.

**How to avoid:**
1. Check mode before attempting scoring
2. Check response.retrieved_contexts exists and non-empty
3. Wrap scoring in try/except with warning

**Warning signs:** AttributeError or empty metric values in query command output.

**Code pattern:**
```python
if mode == "hybrid" and response.retrieved_contexts:
    try:
        # Score only if we have contexts
        ragas_eval = ragas_service.evaluate_response(...)
    except Exception as e:
        logger.warning(f"Scoring failed: {e}")
```

### Overall Score Normalization Fix

```python
# Source: src/application/use_cases/evaluate_model.py
# Location: _calculate_category_weighted_score method (lines 310-371)

def _calculate_category_weighted_score(
    self,
    results: List[EvaluationResult]
) -> float:
    """
    Calculate overall score using category-level weighting.

    Fixed in Phase 2.2: Normalize by sum of weights for present categories.
    """
    if not results:
        return 0.0

    # Get all evaluation categories
    categories = EvaluationCategory.get_all_categories()

    # Group results by category
    category_scores = {}
    total_weight = 0.0  # NEW: Track total weight

    for category in categories:
        category_results = [
            r for r in results
            if r.test_case.benchmark_type.short_name in category.benchmarks
            and r.overall_score is not None
        ]

        if category_results:
            category_avg = sum(r.overall_score for r in category_results) / len(category_results)
            category_scores[category.name] = {
                "average": category_avg,
                "weight": category.weight,
                "count": len(category_results)
            }
            total_weight += category.weight  # NEW: Accumulate weights

            self._logger.info(
                f"Category '{category.name}': {category_avg:.2%} "
                f"(weight: {category.weight:.0%}, tests: {len(category_results)})"
            )

    # Calculate weighted overall score
    if not category_scores:
        return sum(r.overall_score for r in results if r.overall_score is not None) / len(results)

    weighted_sum = sum(
        cat["average"] * cat["weight"]
        for cat in category_scores.values()
    )

    # NEW: Normalize by total weight of present categories
    normalized_score = weighted_sum / total_weight if total_weight > 0 else 0.0

    self._logger.info(
        f"Category-weighted overall score: {normalized_score:.2%} "
        f"(weighted sum: {weighted_sum:.4f}, total weight: {total_weight:.2f})"
    )

    return normalized_score  # FIXED: Was returning weighted_sum directly
```
