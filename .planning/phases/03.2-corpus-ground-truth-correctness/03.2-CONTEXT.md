# Phase 3.2: Corpus and Ground Truth Correctness - Context

**Gathered:** 2026-04-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Merged phase combining former 3.2 (ingestion correctness) and 3.3 (ground truth clause audit). Two sub-goals executed sequentially in a single phase to reduce orchestration overhead (one CONTEXT, one research, one verification, one closeout).

**Sub-goal A — Corpus re-ingestion correctness (bugs #9, #10):**
Fix the clause-aware chunker so sections 5.3 and 5.4 of CCoP 2.0 are no longer dropped from the Qdrant index. Re-ingest all 8 PDFs with the fixed chunker. Verify every chapter from every source document is present in the index with correct citation IDs.

**Sub-goal B — Ground truth clause audit (bug #8):**
Every ground truth test case's `expected_clause` reference is validated against the actual CCoP PDFs. Hallucinated citations are flagged, corrected (human-in-the-loop), or deprecated. Ground truth emerges clean and protected by a hard-fail validator against future regression.

**Sequencing:** Sub-goal A ships first because sub-goal B's semantic mismatch audit reads clause text from the re-ingested Qdrant index.

**In scope:**
- Clause regex extension for item-letter notation (`5.3.1(a)`)
- Removal of the <30-word merge rule
- Table/figure handling as separate chunks with type metadata
- Corpus re-ingestion with fixed chunker
- Clause inventory extraction script and artifact
- Ground truth audit (clause ID existence + semantic mismatch)
- Audit report (markdown + JSON diff)
- Ground truth validator (manual script)

**Out of scope:**
- Retrieval quality tuning beyond ingestion fixes (Phase 4)
- Ground truth regeneration from scratch (future Phase 1 revisit)
- CI integration for the validator (manual-run only per user decision)
- Retriever or reranker changes (Phase 4)
- New benchmarks or test cases

<decisions>
## Implementation Decisions

### Sub-goal A — Chunk granularity and ingestion

**Approach: Fix current (leaf).** Extend the existing clause-aware chunker rather than redesign.

**Leaf depth: Clause-level only.**
- Regex matches `X.Y.Z` form (current) and extends to `X.Y.Z(letter)` notation if present, but chunks stop at clause level. Item-letter sub-items (e.g., `(a)`, `(b)`, `(c)`) remain embedded inside parent clause text.
- Rationale: preserves current citation precision, keeps chunk count manageable (~180 chunks), avoids explosion to 300+ chunks that item-letter leafing would produce.

**Merge rule: Remove entirely.**
- The current `<30-word merge` rule (clause_aware_chunker.py:96-108) is the root cause of bug #9 — short clauses get buffered and appended to the next clause, crossing section boundaries and producing chunks with incorrect citation IDs.
- Every clause match becomes its own chunk regardless of word count. Short chunks (5-15 words) are acceptable because hybrid retrieval (dense BGE + sparse BM25) handles them well.

**Tables and figures: Separate chunk with type metadata.**
- Tables become their own chunks with `metadata.type = "table"` and a `parent_clause` reference to the enclosing clause ID.
- Addresses the appendix-matrix loss that contributes to bugs #9/#10 for sections 5.3/5.4 (matrix blocks break the clause regex; current chunker skips content until the next clause match).
- Enables filtered retrieval (e.g., "tables only" queries).

**Verification for sub-goal A:**
- Chapter-level coverage test: every chapter from every one of the 8 source PDFs has at least one chunk in the index.
- Sections 5.3 and 5.4 specifically asserted present.
- Chunk boundary regression test: no chunk contains text from two distinct clause IDs.
- TOC sanity test: chunks generated for clauses listed in each PDF's table of contents.

### Sub-goal B — Clause inventory artifact

**Durability: Durable, committed to repo.**
- Extraction script produces the inventory; output JSON is committed to the repo as a first-class fixture.
- Ground truth validator imports it. Re-runnable via the extraction script when PDFs update.

**Location: `src/rag/ingestion/fixtures/clause_inventory.json`.**
- Co-located with the ingestion code that produces it and the validator that consumes it.
- Versioned alongside chunker changes.

**Generation: Automated extraction script.**
- Uses Docling (already in the ingestion pipeline) to parse the 8 CCoP PDFs and emit the structured inventory.
- Reproducible; no manual curation drift.
- Script lives under `src/rag/ingestion/scripts/` (or equivalent) and is runnable standalone.

**Schema: Minimal — `{clause_id, source_doc}` per entry.**
- Just enough to answer "does this clause exist in this document?"
- Small file, fast to load, no drift risk on ancillary fields (titles, pages).
- Semantic mismatch check sources clause **text** from the re-ingested Qdrant index at audit time (filter by `citation_id`), not from the inventory — this is why sub-goal A must ship before sub-goal B.

### Sub-goal B — Audit correction boundary

**Correction aggressiveness: Flag-for-human-review only.**
- Audit emits a report listing every flagged case with suggested nearest-match clause.
- Human reviews and manually updates ground truth JSON files.
- No silent auto-correction — every change is intentional and traceable.

**Report format: Markdown report + JSON diff.**
- Human-readable `.md` listing every flagged case with context (current citation, suggested correction, confidence, reason).
- Machine-readable `.json` diff recording `{test_id, old_clause, new_clause, reason, reviewer, date}` for every accepted correction. Supports review and replay.
- Report artifact lives in `.planning/phases/03.2-corpus-ground-truth-correctness/` (phase-scoped).

**Scope of audit: Clause ID existence + semantic mismatch.**
- Pass 1: does the `expected_clause` exist in the clause inventory? Flag if no.
- Pass 2: does the test case's `expected_response` semantically match the clause body (retrieved from Qdrant by `citation_id`)? Flag mismatches.
- Semantic comparison method: left to planner (options: embedding similarity threshold, LLM-as-judge, or both).
- Out of scope: completeness audit (is every CCoP clause covered by at least one test case?).

**Unsalvageable test cases: Mark deprecated, exclude from eval.**
- Add `status: "deprecated"` field to the test case JSON.
- Eval pipeline skips deprecated cases.
- Preserves history; downgrades bad data without deletion; flagged for future Phase 1 regeneration.

### Sub-goal B — Validator enforcement

**Enforcement: Hard-fail after audit complete.**
- Last plan in Phase 3.2 enables the validator in hard-fail mode (script exits non-zero on any invalid citation).
- By that point, sub-goal B has corrected or deprecated every flagged case, so the validator is green on clean ground truth.
- Prevents future regression — a new test case with a hallucinated citation fails the validator locally before commit.

**Execution: Manual script only.**
- Command: `poetry run ccop-eval validate-ground-truth` (or similar subcommand).
- Not wired into CI, not wired into pre-commit hooks, per explicit user decision.
- Developer runs the script as part of their ground truth editing workflow. Honor system + local discipline.

**Semantic gate: Hard-fail like ID existence checks.**
- Both the ID existence check and the semantic mismatch check exit non-zero in the validator.
- User accepts the false-positive risk in exchange for stronger regression prevention.

### Claude's Discretion

- Exact regex extension for item-letter notation within the clause regex (matching `(a)`, `(b)`, ... at end-of-line vs inline).
- Table detection heuristic (Docling metadata vs pipe-count heuristic on markdown).
- Schema for the JSON diff correction log (beyond the required fields above).
- Semantic comparison method (embedding similarity threshold value, LLM-as-judge prompt, hybrid).
- Exact location of the audit report artifact within the phase directory.
- Exact location of the extraction script.
- Whether the validator script re-loads the clause inventory fresh each run or caches it.

<specifics>
## Specific Ideas

- **Sub-goal A unblocks sub-goal B semantic audit.** The minimal inventory schema (`{clause_id, source_doc}`) is intentional — semantic mismatch check reads clause body text from the re-ingested Qdrant index at audit time. This coupling dictates execution order: A before B.
- **Removing the merge rule is the smallest possible change that fixes bug #9 deterministically.** No configuration knob to tune; the failure mode is eliminated, not merely reduced.
- **Tables get `metadata.type="table"` so future retrieval-quality work (Phase 4) can apply different scoring or filtering to structured content.** Also unlocks targeted queries like "show me only the CCoP enumeration tables."
- **Inventory lives under `src/rag/ingestion/fixtures/`** to signal it is produced and consumed by the RAG module. Keeps ground-truth validation logic deterministic and free of Qdrant lookups at validation time (Qdrant is only needed for the semantic audit pass during Phase 3.2, not for ongoing validation).
- **Deprecated test cases stay in ground truth files** (not deleted) so the evaluation history remains traceable and future Phase 1 regeneration has full context on what was removed and why.

</specifics>

<deferred>
## Deferred Ideas

- **Item-letter-level leaf chunking (`5.3.1(a)` as its own chunk).** Considered but deferred — would grow chunk count to ~300+ and add citation-precision surface area that current ground truth doesn't exercise. Revisit if Phase 4 retrieval quality motivates it.
- **CI integration for the validator.** User declined manual-only for now. Revisit when the project has multiple contributors or when ground truth edits become frequent.
- **Pre-commit hook integration.** Same reasoning as CI — deferred pending workflow change.
- **Completeness audit** (does every CCoP clause have at least one test case?). Different problem from correctness; belongs to a ground-truth-expansion phase.
- **Ground truth regeneration from scratch.** If the audit reveals a high rate of unsalvageable cases, a future phase may rebuild ground truth from the inventory rather than patching. Not triggered automatically.
- **Rich clause inventory schema** (titles, pages, hierarchy paths). Minimal schema is sufficient for Phase 3.2 audit needs. Can be extended in a later phase if validators or tooling need more fields.
- **Auto-correction with confidence threshold.** Flag-for-human-review chosen for safety; auto-correction could be added later once the audit surface area and error taxonomy are better understood.

</deferred>
