## Ground-Truth Citation Survey (informs extension decision)

Before approving the extension, a survey of all `clause_reference` and `expected_response` clause citations across the 118 ground-truth test cases found:

- **Cybersecurity Act 2018 citations in GT:** 57 total, all using `section N` or `Part N` format — 0% coverage by pre-extension inventory (Cybersecurity Act had 0 entries)
- **Supporting guides citations in GT:** 0 (Auditing Guidelines, Threat Modelling Guide, Risk Assessment Guide, Security By Design, CCoP Response to Feedback are referenced contextually but never cited as `clause_reference` in a test case) — no additional extraction work required for those docs

This finding is what motivated the extension: without the legal-numbering pass, sub-goal B's validator would hard-fail on 57 Cybersecurity Act citations even if they are correct, because the inventory would report zero coverage for the document.

## Decisions Made

- **Minimal schema preserved** — `{clause_id, source_doc}` only, per CONTEXT.md lock. Test `test_every_entry_has_exactly_two_keys` makes drift impossible.
- **Item-letter synthesis via positional pairing** — Docling embeds `- (c) ...` as list items within parent clause body, not as standalone headings. Pass 2 walks Pass-1 clause positions and pairs `- (letter)` matches with the nearest preceding clause heading.
- **Extension accepted after user review** — Zero-coverage of Cybersecurity Act 2018 would have silently passed the audit (no citations to validate if no inventory entries), but the 57 GT citations would have been un-auditable. Extending the inventory to cover legal numbering closes this gap.
- **Roman numeral output dropped** — Original spec's `[IVX]+` Part regex produced 0 matches against the actual PDF. Emitted `Part <N>` strings kept in clause_id to preserve validator contract.

## Deviations from Plan

### Deviation 1 — Extension scope: legal-numbering pass for Cybersecurity Act 2018

**User-approved mid-plan extension. Not an autonomous deviation.**

- **Found during:** Checkpoint review after Tasks 1+2 committed
- **Issue:** Initial 620-entry inventory had 0 entries for Cybersecurity Act 2018. Ground-truth citation survey found 57 GT citations against this document in `section N` / `Part N` format. Sub-goal B audit would be unable to validate those citations against an empty document inventory.
- **Fix:** Added a document-scoped legal-numbering pass in `extract_clause_ids(markdown_text, source_doc=...)` that activates only when `source_doc == "Cybersecurity Act 2018"`. Emits `section <N>` for bare-number section headings and `Part <N>` for Part headings.
- **Files modified:** `src/rag/ingestion/scripts/build_clause_inventory.py`, `src/rag/ingestion/fixtures/clause_inventory.json`, `src/tests/rag/ingestion/scripts/test_build_clause_inventory.py`
- **Verification:** `("section 11", "Cybersecurity Act 2018")` now in inventory; 6 `Part N` entries present; test suite grew 10 -> 13
- **Committed in:** `ff06fdb`

### Deviation 2 — Regex adaptation to source format

**Sub-deviation of Deviation 1. User approved after evidence-based clarification.**

- **Found during:** Attempting to implement Extension (Deviation 1) with user's original spec
- **Original spec:**
  - `^section\s+(\d+[A-Z]?)` for sections
  - `^Part\s+([IVX]+)` for Parts (Roman numerals)
- **Issue:** Docling-rendered Cybersecurity Act 2018 PDF contains:
  - ZERO occurrences of `^section\s+\d+` — sections render as bare-number `11. Powers of Commissioner`
  - ZERO occurrences of Roman numeral Parts — Parts render as Arabic `## Part 1 PRELIMINARY` through `## Part 6 GENERAL`
- **Fix (approved):**
  - Section regex adapted to `^(\d+[A-Z]?)\.\s+[A-Z]` (bare-number heading), emitted clause_id preserved as `section <N>`
  - Part regex adapted to `^(?:##\s+)?Part\s+(\d+)` (Arabic with optional `##` prefix), emitted clause_id preserved as `Part <N>`
- **Process observed:** Instead of silently adapting or failing verification, paused at evidence-with-options prompt (pattern-match counts, sample lines, three alternatives). User approved Option 1 (adapt regex, preserve emitted clause_id contract).
- **Verification:** Cybersecurity Act 2018 contributes 53 entries (47 sections + 6 Parts) after adaptation
- **Committed in:** `ff06fdb`

## Issues Encountered

Fixed by padding to fixed depth (4 numeric slots) with a trailing string slot, giving all tuples identical shape. Later extended to prefix with a group-tag integer (0/1/2) to support heterogeneous CCoP/Part/section ID formats.
