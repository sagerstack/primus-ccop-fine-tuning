## Decisions Made

- CLAUSE_PATTERN extended with `^(?:##\s+)?` non-capturing group to match both Docling heading formats. The `##` prefix is the root cause of bug #10 — not item-letter notation as initially suspected. Item-letter notation (`- (a)`, `- (b)`) appears as list items within clause bodies, not as standalone headings.
- Optional `(?:\([a-z]\))?` group retained per plan requirement even though it's not exercised by the actual document heading format. Harmless and future-proof.
- Merge rule removed entirely (not reduced or tuned). Any configuration knob would preserve the bleed risk.
- Loop index fixed to `i = 1` unconditionally — discovered during test writing, applied as Rule 1 bug fix.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed inverted loop start index in chunk_by_clauses**
- **Found during:** Task 3 (writing regression tests)
- **Issue:** `i = 1 if parts[0].strip() else 0` is backwards. When `parts[0]` is empty (no pre-clause preamble in test fixtures), `i` was set to 0, causing the loop to read `parts[0]=""` as clause number, `parts[1]` as heading, `parts[2]` as content — producing incorrect chunks. The bug was masked in production because real CCoP documents always have preamble text before the first clause.
- **Fix:** Changed to `i = 1` unconditionally with an explanatory comment. Clause groups always start at index 1 in the split result regardless of preamble presence.
- **Files modified:** `src/rag/ingestion/chunkers/clause_aware_chunker.py`
- **Verification:** All 11 previously-failing behavioral tests now pass. Real-document chunking (246 chunks) unchanged.
- **Committed in:** `a3fe151` (Task 3 commit)

## Issues Encountered

- **Heading format discovery:** The plan's description of item-letter notation (`5.3.1(c)`) as a heading boundary was based on bug #10 analysis text, not observation of the actual Docling output. In practice, `5.3.1(c)` appears as `- (c) Implement...` (a list item) within the 5.3.1 body. The real missing boundary was the `##` prefix on 56 headings. The plan's regex fix was directionally correct; the actual fix required a different extension (`^(?:##\s+)?` prefix rather than `\([a-z]\)` suffix as the primary fix). Both were implemented.
